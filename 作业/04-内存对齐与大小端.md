## 3. `[考：知识点1]` 对比题

```c
struct S3a { char c; int i; char d; };
struct S3b { int i; char c; char d; };
```

两个结构体成员相同、顺序不同，sizeof 各是多少？**为什么差**？

**答**：
sizeof(S3a) == 12;
sizeof(S3b) == 8;
因为S3a开始是char，后面剩3字节放int，int需要4字节，放不完，所以int需要对齐新的字节，而char后面的三字节则需要padding。int占了4字节后，最后一个char有需要在新的字节对齐，后面需要补上3字节的padding

## 4. `[考：知识点2]` 概念

为什么编译器要给结构体加 padding？对齐的本质是拿什么换什么？

**答**：因为需要字节对齐，cpu每次读取数据都是按字来获取的，如果字节不对齐，那么存在一个数据占前面字的一部分，又占后面字的一部分，这样获取数据前需要先分割再合并，最后处理数据。对齐的本质是空间换时间。

**答**：sizeof = 6。代价1:数据处理会慢，2.忘了

## 9. `[考：知识点5]` 手写题（面试原题级别）

不看课本，凭记忆写一个程序判断当前机器是大端还是小端。**两种写法**（指针法 + union 法）都写：

**代码（指针法）**：
#include<stdio.h>
#include<stdint.h>
int main(void){
    uint32_t x = 0x12345678;
    uint8_t * p =(uint8_t *)&x;
    printf("%s\n",*p == 0x12 ? "大端 big-endian":"小端 little-endian"); 
}

**代码（union 法）**：
#include<stdio.h>
#include<stdint.h>
union {
    uint32_t x;
    uint8_t b[4];
}s;
int main(void){
    s.x= 0x12345678;
    printf("%s\n",s.b[0] == 0x12 ? "大端 big-endian":"小端 little-endian"); 
}

## 10. `[考：知识点4b]` 概念

`htons` 四个字母各是什么意思？为什么网络通信需要它？

**答**：不知道，课本上好像没写，我等下查一下资料
资料：
htons:host to network short 16位 主机->网络
htonl:host to network long  32位 主机->网络（常用于ip地址）
htohs:Network to Host Short 16位 网络->主机（接受数据时读端口）
ntohl:Network to Host Long  32位 网络->主机（接受数据时读ip）
核心作用：将一个16位的整数，冲主机字节序转换为网络字节序
1.为什么要用htons？因为主机字节序是小端序，网络字节序是大端序，如果不进行转换，客户端直接发送，服务器读出来的数据会完全错乱
2.典型使用场景（端口号）htons最经典的用法是给端口号赋值。在填充sockaddr_in结构体时，必须使用它
3.一个暗坑：对数据载荷（payload）使用htons。正确使用方式是，只用于端口号和协议号，错误使用方式：如果传输的是文本，或文件二进制流，绝对不要使用htons，它只改变2字节的树枝，用在数据流上会打乱字节顺序，且造成数据截断。
