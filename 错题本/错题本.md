### 错题 1：gcc 编译的四个阶段是哪几个？对应什么标志？（课本 00-开发环境）

**我的错误答案**：预处理、编译、链接、运行；标志 -E、-S、-o、然后链接。

**正确答案**：**预处理 → 编译 → 汇编 → 链接**（"运行"不算编译阶段）。
- 预处理 `-E` → `.i`
- 编译   `-S` → `.s`
- 汇编   `-c` → `.o`
- 链接   不加 -E/-S/-c，直接 `gcc hello.o -o hello`
- `./hello` 是**运行**，不是编译阶段。

**为什么错**：
1. 漏掉了"汇编"这一阶段，却把"运行"当成了阶段。
2. 把 `-o`（给输出文件起名）误当成汇编阶段的标志；汇编其实是 `-c`。
3. 把链接那步（`gcc hello.o -o hello`）贴成了"运行"标签；真正的运行是 `./hello`。

**相关知识点**：课本/01-C内功/00-开发环境.md「gcc 编译的四个阶段」。

### 错题 2：清零用了 `!` 而不是 `~`（作业 01-位运算）

**我的错误答案**：`reg &= !(1U<<2);`

**正确答案**：`reg &= ~(1U << 2);`

**为什么错**：把 `~`（按位取反）写成了 `!`（逻辑非）。`!` 只返回 0 或 1：`!(1U<<2)` = `!4` = `0`，于是 `reg &= 0` 把 reg **所有位**全清零了，根本不是"只清 bit2"。清零靠的是"和 0 做与"，必须用 `~` 造出"只有 bit n 为 0、其余为 1"的掩码。

**相关知识点**：课本/01-C内功/01-位运算.md「② 清零」。

### 错题 3：位移算错了位（作业 01-位运算）

**我的错误答案**：`1U<<2` 后 reg = `0b01000000`。

**正确答案**：`1U<<2` = `0b00000100`（= 0x04）。

**为什么错**：bit0 是**最右边**那一位，不是最左边。`1U<<n` = 把 1 放到"从右数第 n 位"。我把方向搞反了，`0b01000000` 其实是 `1U<<6`。记不准就 `printf("%02X", reg)` 验证。

**相关知识点**：课本/01-C内功/01-位运算.md「进阶贴士·位编号」。

### 错题 4：以为"64 位系统 int 就是 8 字节"（作业 02b Q4/Q7）

**我的错误答案**：Q7 预测 `sizeof(a)=40`（以为 int 8 字节）；Q4 用 `sizeof(p+1)` 测步长得 8 8。

**正确答案**：64 位只改变**指针**宽度（4→8），**int 仍是 4 字节**（LP64 约定）。所以 Q7 = 20 8；步长要用**地址差**测：`(char*)(p+1) - (char*)p` = 4，`(c+1) - c` = 1。

**为什么错**：
1. 混淆"机器位数"和"类型宽度"——位数只决定地址/指针多宽，不决定 int 多宽。
2. 掉进工具坑：`sizeof(任何指针表达式)` 永远返回 8（指针本身的大小），**测不出步长**。测步长两种正确姿势：地址差，或 `sizeof(*p)`（万能等式：**步长 = sizeof(\*p)**）。

**相关知识点**：课本/01-C内功/02b-指针与数组.md「知识点3 步长」「知识点6 数组 vs 指针」。

### 错题 5：for 循环里 `p++` 和 `p+i` 双进指针（作业 04 Q11）

**我的错误答案**：`for(i=0;i<4;i++,p++) printf(...(p+i)...p[i]...)`，输出 DD BB 02 00，后两个是垃圾值。

**正确答案**：二选一——要么 `for(i=0;i<4;i++)` 用 `p[i]`/`p+i`（指针不动），要么 `for(;p<x+4;p++)` 用 `*p`（指针动）。混用 = 指针一次前进两步 → 跳字节 + 越界读垃圾。

**为什么错**：没意识到 `p++`（每轮末尾推进 p）和 `p+i`（按下标偏移）是**两种独立的推进方式**，叠加使用双倍步进。越界读不报错，只出乱码——这次亲眼见了。

**相关知识点**：课本/01-C内功/02b-指针与数组.md「知识点4 遍历」；作业 04 Q11 越界现场。

### 错题 6：结构体布局漏算 padding（作业 04 Q1）

**我的错误答案**：`struct {char; short; int}` 布局写成 0:c / 1-2:s / 3:i。

**正确答案**：0:c / **1:padding** / 2-3:s / 4-7:i，sizeof = 8。short 的偏移必须是 2 的倍数，char 后面要补 1 字节；int 偏移必须是 4 的倍数。

**为什么错**：只想着"塞满空隙"，忘了**每个成员自己的对齐要求**。口诀：**逐成员过一遍"偏移是不是自己大小的倍数"，不是就补**；最后总大小补到最大成员的倍数。

**相关知识点**：课本/01-C内功/04-内存对齐与大小端.md「知识点1 三条规则」。

### 错题 7：.data 和 .bss 记反（作业 06 Q2/Q12）

**我的错误答案**：已初始化全局 → .bss、未初始化 → .data（Q2 四个全错）；"初始化后占文件体积的是 .bss"。

**正确答案**：**非零初始化 → .data（值占文件体积）；未初始化 / 全零初始化 → .bss（不占文件，加载时清零）**。static 局部/全局同样按"初始化没初始化"分。

**为什么错**：两个区的名字和分工没有建立锚点。口诀：**.bss = "Better Save Space"（全零数据省空间，不占文件）**；.data = 真有数据（data）要写进文件。

**额外学到**：`int big[N] = {0};` gcc 会优化进 .bss（全零初始化语义等同未初始化），想看到 .data 占体积必须 `= {1}` 非零。**预期和实测不符时别放过**——这次就是 gcc 的优化在捣乱。

**相关知识点**：课本/01-C内功/06-栈堆与内存布局.md「知识点1 五大区」「知识点7 .data/.bss」。

### 错题 8：`>` 重定向后报错还在屏幕上，以为"环境不对"（作业 10 Q8c）

**我的错误答案**："中间两个命令应该是我输入有问题，我电脑环境哪里不对，这两条命令我没看懂。"

**正确答案**：每个命令有两个输出口——stdout(1) 和 stderr(2)。`>` 只接管 stdout，所以报错（走 stderr）照上屏、文件被创建但为空；`2>` 接管 stderr；`2>&1` 合流。这是设计不是故障。

**为什么错**：只记了"> 是重定向"，没建立"两个口分流"的模型。其实在用 `2>/dev/null` 和 `2>&1 | tee` 时都已经对了，看到反直觉现象时没往这上面想。

**相关知识点**：课本/03-Linux/10-命令行与shell基础.md「知识点6 管道与重定向」。

### 错题 9：以为 shell 会先搜当前目录再搜 PATH（作业 10 Q11a）

**我的错误答案**："shell 先从当前目录下查看是否有 gcc 命令，没有的话，再从 path 的地址下面找。"

**正确答案**：bash **不搜当前目录**（那是 Windows cmd 的行为），只按 PATH 从左到右找。所以当前目录下的程序必须 `./a.out` 明写——`./t.sh: Permission denied` 那次其实已经是这个机制在起作用。

**为什么错**：把 Windows 的习惯带过来了。安全设计：不搜当前目录可防止恶意程序冒充系统命令。

**相关知识点**：课本/03-Linux/10-命令行与shell基础.md「知识点8 环境变量」。

### 错题 10：内存对齐只答了"总大小"，把最核心的规则①丢了（08 模拟 Q6）

**我的错误答案**：「最终需要向最大的那组数据类型进行对齐，数据大小需要是 4 字节的倍数」；取消对齐的关键字忘了。

**正确答案**：三条规则：①**每个成员的偏移 = 自身大小的整数倍**（不够就补 padding——这条才是徒手算布局的核心）②总大小 = 最大成员的整数倍 ③嵌套结构体看内层最大成员。对齐基数不是固定 4——最大成员是 double 时按 8。取消对齐：`#pragma pack(1)` 或 `__attribute__((packed))`；代价：慢 + 某些 ARM 非对齐访问直接崩。

**为什么错**：只背了"结果长什么样"（总大小对齐），丢了"怎么算出来的"（逐成员查偏移）。「4 字节」是想当然——int 是 4 不代表所有对齐都按 4。

**相关知识点**：课本/01-C内功/04-内存对齐与大小端.md「知识点1 三条规则」。

### 错题 11：函数指针声明整个想不起来（08 模拟 Q8）

**我的错误答案**：「这个我忘了」。

**正确答案**：`int (*p)(int, int) = add;`——`(*p)` 的括号必须有，否则 `int *p(int,int)` 变成"返回 int* 的函数声明"。它是 qsort 比较器、内核 file_operations（ops 表）的核心机制，也是 C03 虚函数（vtable）的地基——**编译器替你维护的函数指针表**。

**为什么错**：学的时候靠例子认得（`cmp_t`），没闭眼徒手写过一遍声明。"看着会、闭眼写不出"，正是面试白板题的分水岭。

**相关知识点**：课本/01-C内功/05-预处理宏与typedef.md「函数指针」；课本/02-C++/C03-继承与多态.md「知识点4 虚表」。

### 错题 12：以为 print(3.14f) 调的是"float 版重载"（作业 C01 Q5）

**我的错误答案**：「调用的是 float 的那个，因为 3.14f 也是 float 的数据格式」。

**正确答案**：代码里只写了 int / double / const char* 三个版本，**根本没有 float 版**。重载匹配规则：**精确匹配 > 提升（promotion）> 转换**。float 没有精确匹配，**提升为 double**，调的是 print(double)（已实测验证：输出 "--> double"）。float→double 是无损"提升"，double→float 才叫窄化转换。

**为什么错**：看到输出 3.140000 就脑补了一个不存在的重载，没回头核对自己写的三个函数签名。**答"调了哪个"之前，先数一遍候选名单**。

**相关知识点**：课本/02-C++/C01-从C到C++.md「知识点4 重载」。

### 错题 13：深拷贝构造的"口述版"写成了浅拷贝（作业 C02 Q9）

**我的错误答案**：「函数体需要先 new Buf，再 this.data = other.data」

**正确答案**：深拷贝三步：① `new` 一块**自己的**内存（长度 `strlen(other.data)+1`）② `strcpy` 把**内容**拷进来 ③结束。`this->data = other.data` 拷的是**指针本身**——两个对象指向同一块堆内存，这正是浅拷贝，也是 double-free 的根源。

**为什么错**：代码写对了（Q8 的 06.cpp 是标准深拷贝），口述时却说成了指针赋值。**会写不会说，面试照样挂**——代码是手，口述是嘴，两只手都要练。

**相关知识点**：课本/02-C++/C02-类与对象.md「拷贝构造与深浅拷贝」。

### 错题 14：虚析构预测写反了，还没对照自己贴的运行结果（作业 C03 Q9a）

**我的错误答案**：预测"不加 virtual：Base 构造、Derived 构造、Derived 析构"（以为 ~Derived 会跑、~Base 不跑）。

**正确答案**：**Base 构造、Derived 构造、Base 析构**——delete 按指针的静态类型（Base*）只调 ~Base，**~Derived 没执行**，`new int[100]` 的 400 字节泄漏。ASan 报 new-delete-type-mismatch。加 virtual 后：Derived 构造 → **Derived 析构 → Base 析构**（链式全跑）。

**为什么错**：①把"静态决定"的方向理解反了（非虚 = 按指针类型，只认 Base*）；②**自己贴的运行输出就是正确答案，预测完没回头逐行对照**——预测-验证闭环断在最后一步，等于白预测。

**相关知识点**：课本/02-C++/C03-继承与多态.md「知识点7 虚析构」。

### 错题 15：把 d.name 编不过的原因归给 const（作业 C03 Q1）

**我的错误答案**："name 是 const，初始化之后不能再修改了"。

**正确答案**：`const char * name` 里 const 修饰的是**指向的字符**，**指针本身可以改**（02b const 双子：`*` 左 const → 数据只读）。`d.name = "xx"` 编不过的**唯一原因是 protected**——只有基类和派生类的类内能碰，main 和普通函数都是外界。

**为什么错**：把两条规则（访问级别 + const 位置）叠在一起，把真正起作用的那条说丢了。const 双子在 02b 明明学过——**单独会、合着就糊**，说明还没长成"条件反射"。

**相关知识点**：课本/01-C内功/02b-指针与数组.md「const 指针」；课本/02-C++/C03-继承与多态.md「知识点1 protected」。

### 错题 16：`s += *c` 拼字符串，结果只拼了一个字符（作业 C04 Q2）

**我的错误答案**：「s += \*c，c 的内容是地址，\*c 是 c 里面的内容」。

**正确答案**：`s += c;` —— string 有 `operator+=(const char*)`，认得 C 字符串指针，自动 strlen 整个拼上。`*c` 解引用得到的是**第一个字符 `'w'`（一个 char）**，`s += *c` 走的是 `operator+=(char)`，**能编译、能运行、不报错**，但只拼一个字母——实测输出 "hellow"。

**为什么错**：把"指针"和"指针指向的东西"又混了（02b 的老朋友）。最险的不是写错，而是**猜的版本不报错**——只有对着输出才看得出少拼了。C 字符串本身就以"指向首字符的指针"的身份到处传，直接给接口，别自己解引用。

**相关知识点**：课本/02-C++/C04-STL实战.md「知识点1/2 string 与 C 串的桥」。

### 错题 17：const 引用形参里手写 `iterator` 编译错，误以为"迭代器用不了了"（作业 C04 Q5）

**我的错误答案**：「引用传过去之后迭代器的写法用不了了……地址还是原来的地址，为啥 begin 和 end 用不了了呢？」

**正确答案**：`const std::vector<int>& v` 里 v 是 const，`v.begin()` 调的是 **const 重载**，返回 **const_iterator**（只读迭代器），赋给手写死的 `std::vector<int>::iterator`（可写迭代器）→ 编译错 `conversion from const_iterator to iterator requested`。**迭代器没废，是型号拿错了**。写 `auto a = v.begin()`（让编译器挑对类型）或 `std::vector<int>::const_iterator` 即可。

**为什么错**：不知道 begin() 有 const / 非 const 两个版本。范围 for 能用，是因为它内部替你选对了类型。口诀：**遍历 const 容器，迭代器一律 auto，别手写类型**。

**相关知识点**：课本/02-C++/C04-STL实战.md「知识点4 迭代器」。

### 错题 18：比较器写 `>=`，4 个元素没崩，归因为"不同编译器效果不一致"（作业 C04 Q9）

**我的错误答案**：「从结果上来看似乎没什么区别，不能写等号是不同编译器的效果不一致吗？导致不够稳定？」

**正确答案**：比较器必须满足**严格弱序**：`cmp(a,a)` 必须为 false。`a.score >= b.score` 在两元素相等时返回 true，sort 内部逻辑会**越界**。4 个元素走小数组插入排序侥幸没炸；同一段代码、同一位比较器，喂 10 万个同分元素（score 只有 0/1/2）实测 **Segmentation fault**（exit=139）。正确写法：严格小于（`>`），相同分再比名字。

**为什么错**：拿"没崩"当"没错"。UB 的判定依据是**规则**（cmp(a,a) 必须为 false），不是运行结果——数据不够狠而已，不是编译器差异。

**相关知识点**：课本/02-C++/C04-STL实战.md「知识点6 sort 与比较器」。

### 错题 19：修迭代器失效的方案二写成"判断 p 是否为 null"；且把 UAF 猜成"泄漏"（作业 C04 Q6）

**我的错误答案**：「在使用 p 之前，判断是否 p 指向 null，如果是悬空指针，则重置」；预测时报错名「可能是内存泄漏相关的」。

**正确答案**：**悬空指针 ≠ NULL**。p 里存的是"已被释放内存的老地址"，是一个看起来完全正常的值，**程序无法检测**；判 null 只能查出"从没指过东西"的指针。标准修法两条：① 改完 vector 后**用前重取** `p = &v[0]`；② `v.reserve(N)` 提前征够容量，搬家不发生，p 永远有效。报错名也是两码事：**heap-use-after-free = 释放了还在用；泄漏 = 没人释放**。

**为什么错**：把"悬空"和"空"当成一回事——C03 虚析构里 dangling 的本质就见过：指针还存着老地址，但那块地已经不属于你。报错名词背得不牢，现场猜就猜飞了。

**相关知识点**：课本/02-C++/C04-STL实战.md「知识点3 搬家与失效」；课本/01-C内功/06-栈堆与内存布局.md「四大堆错误」。

### 错题 20：循环引用预测 "~Node 打 4 次"，实际 0 次（作业 C05 Q6a/b）

**我的错误答案**：预测 4 次；跑完没有任何 ~Node 打印，追问"为什么没有打印呢？"，没把预测和实测对上。

**正确答案**：**0 次**。循环引用下 a、b 的引用计数**永远到不了 0**（你手里的 a 死了，b->next 还牵着它），计数不为 0 → 析构不跑 → 打印 0 次 + ASan 报泄漏。改成 weak_ptr 后 2 次。

**为什么错**：预测时没把"计数决定析构"这条规则推到底——数一下"谁还牵着谁"就该得出 2→1 卡住、0 次打印。更严重的是**预测 4 次 vs 实际 0 次**这么大的反差都没触发回头检查（错题14 同款：预测-验证闭环断在最后一步）。

**相关知识点**：课本/02-C++/C05-内存与进阶.md「知识点3 循环引用」。

### 错题 21：lambda 值捕获以为第二次调用会看到新 base（作业 C05 Q9）

**我的错误答案**：预测 `101 101 102 base=101`（第三个 f1(1) 以为是 102）；实测第三个还是 101，没想通。

**正确答案**：`101 101 101 base=101`。**值捕获在 lambda 定义那一刻就拷贝定格**——f1 的 base 是定义时拍的"照片"（100），之后外面的 base 改成什么都与它无关，永远 100+1=101。f2 是引用捕获（"镜子"），照的是外面那个 base 本尊。实测：定义后把 base 改成 999，photo(1) 仍 101，mirror(1) = 1000。

**为什么错**："值捕获会拷贝一份数据"这句说对了，但没落到"**什么时候拷**"——是定义时拷，不是调用时拷。单独会、追起来就糊。

**相关知识点**：课本/02-C++/C05-内存与进阶.md「知识点5 lambda 捕获」。

### 错题 22：把"判空"做成了解引用，moved-from 的 unique_ptr 直接 `*p`（作业 C05 Q3c）

**我的错误答案**：move 之后打印 `*p` → Assertion `get() != pointer()` failed、Aborted；"delete 有没有发生的证据我不太知道"。

**正确答案**：move 后 p 是**空指针**，判空写 `if (!p)`（输出"p 空了"），**不是 `*p`**——解引用空 unique_ptr 就是解引用空指针。delete 的证据：让被管对象带会打印的析构函数（`unique_ptr<Guard>`），花括号一过 "leave" 就打出来。gcc15 的安全网第三次立功（前两次：vector[] 边界断言、lambda？不，是 C04 的 [] 和这次的 operator* 断言）。

**为什么错**："判断 p 是不是空"和"用 p 指的东西"是两个动作，题目要前者我做了后者——和错题19"悬空≠null"是同一片盲区：**指针上能做的"检查"只有和空比，别的检查不存在**。

**相关知识点**：课本/02-C++/C05-内存与进阶.md「知识点2 unique_ptr」。
