## 开发环境速记

- 编译运行：`gcc 源文件 -o 输出`，然后 `./输出`
- 默认带警告+调试编译：`gcc -Wall -g -std=c11 源文件 -o 输出`
- gcc 四阶段口诀：**预 → 编 → 汇 → 链**
  - 预处理（`-E`，`.i`）→ 编译（`-S`，`.s`）→ 汇编（`-c`，`.o`）→ 链接（可执行）
- ⚠️ 易错（踩过坑）：`-o` 是"给输出文件起名"，不是某个阶段；**汇编阶段用 `-c`**（产出 `.o`）。**运行 `./xx` 不属于编译阶段**。
- 我的环境：WSL2 Ubuntu 26.04，gcc 15.2，make 4.4，QEMU 未装（用到再装）

## 位运算速记（四大操作）

- 置位：`reg |=  (1U << n);`
- 清零：`reg &= ~(1U << n);`
- 翻转：`reg ^=  (1U << n);`
- 读取：`if (reg & (1U << n))`
- 多位同时：置位 `reg |= (1U<<a) | (1U<<b);`，清零 `reg &= ~((1U<<a)|(1U<<b));`
- 位编号：bit0 = 最右。`1U<<n` = 2ⁿ：
  - 1U<<0=0x01, <<1=0x02, <<2=0x04, <<3=0x08, <<4=0x10, <<5=0x20, <<6=0x40, <<7=0x80
- ⚠️ 易错（踩过坑）：清零用 `~`（按位取反），**别用 `!`（逻辑非）**。`!(1U<<2)`=`!4`=`0`，`reg &= 0` 会清光所有位。

## 指针速记（基础）

- `&` 取地址，`*` 解引用（按地址取/改东西），互为反操作：`*(&a)` == `a`
- 指针 = 存地址的变量；64 位系统上**指针本身 8 字节**，和指向的类型无关
- 指针类型决定：① 解引用读写几个字节 ② `p+1` 跳多远（下节课详讲）
- ⚠️ 野指针（未初始化）解引用是**未定义行为**，可能崩。解引用前必须让指针指向合法地址（或先 `= NULL`）

## 指针与数组速记（02b）

- 万能等式：**步长 = `sizeof(*p)`**；测步长用**地址差** `(char*)(p+1)-(char*)p`，别用 `sizeof(p+1)`（永远 8）
- 64 位改变的是**指针宽度**（8），**int 仍是 4**（LP64：char 1 / short 2 / int 4 / long 8 / 指针 8）
- `a[i]` ≡ `*(a+i)`；数组名 = 指向首元素的指针，但**能读不能改**（`a++` 报错：不是可修改左值；`a+1` 合法）
- 数组传参立即退化成指针：`void f(int a[])` ≡ `void f(int *a)`，函数内 `sizeof(a)` = 8 → **必须另传长度 n**
- `sizeof(a)`（数组）= 总字节数；元素个数 = `sizeof(a)/sizeof(a[0])`（仅对实参数组成立，传参后失效）
- 指针相减 = **元素个数**，不是字节数（`&a[4]-&a[1]` = 3）
- const 口诀：**`*` 左 const → 数据只读；`*` 右 const → 指针只读**（`const int *p1` vs `int * const p2`）
- `(char*)a` 强转：地址不动，换"眼镜"——按 char 看，步长变 1，可逐字节看内存（04 大小端要用）

## volatile / static / const 速记（03）

- volatile = "每次都老实去内存读写"：**禁止缓存/合并/删除访问**。三个场景：①中断共享变量 ②硬件寄存器 ③多线程共享（仅保可见性）
- ⚠️ volatile **三个不保证**：不原子、不同步、不防打断——多线程正确性靠锁，volatile 只保证"读的是内存"
- 访问硬件寄存器标准姿势：`volatile uint32_t *reg = (volatile uint32_t*)0x40021000;`
- `const volatile int *p` = 代码不许改（const）、硬件随时改（volatile）→ 只读状态寄存器
- static 两副面孔：**局部** → 存静态存储区、只初始化一次、函数返回不销毁；**全局/函数** → 限定本文件可见（防命名冲突，extern 也拿不到）
- 面试一句话：volatile 管优化，static 管生命周期+作用域，const 管只读
- gcc 警告彩蛋：`sizeof` on array function parameter → 该参数已退化成指针

## 对齐与大小端速记（04）

- 对齐三条规则：①成员偏移 = 自身大小整数倍（不够补 padding）②总大小 = 最大成员整数倍 ③嵌套看内层最大成员
- 徒手算布局：逐成员问"偏移是不是自己大小的倍数"，最后总大小补到最大成员倍数
- 成员顺序影响大小：**大成员放前面**省空间（char,int,char=12 vs int,char,char=8）
- packed（`#pragma pack(1)` / `__attribute__((packed))`）：取消 padding。代价：慢 + 某些 ARM 非对齐直接崩。用途：协议头/文件格式/寄存器映射
- 小端 = 低字节在低地址（x86、跑 Linux 的 ARM）；大端 = 网络字节序、老 PowerPC
- 判断大小端：`uint8_t*p=(uint8_t*)&x; *p==0x44→小端`；或 union `b[0]`（union 成员共享首地址）
- ⚠️ 踩过的坑：for 循环里 `i++,p++` 配 `p+i`/`p[i]` → 双倍步进 + 越界读垃圾。**`p++` 和 `p+i` 二选一**
- htons/ntohs/htonl/ntohl：host/network/short/long，只用于端口和 IP 等头部字段，payload 别转

## 预处理与宏速记（05）

- 预处理 = 纯文本替换机器（`.c`→`.i`，`gcc -E`）：不懂语法、不管类型——一切宏坑的根源
- 带参宏两条括号铁律：**每个参数加括号**（防 `a+1` 类优先级）、**整体加括号**（防 `10*ADD()` 类环境）
- ⚠️ 宏参数带副作用（`i++`）会**多次求值**；同一表达式内两次改 i 还是 **UB**（-Wsequence-point 警告）；三目 `?:` 有序、乘法两边无序
- `#define` vs const：宏无类型/预处理期/无作用域；const 有类型有作用域可调试
- 头文件卫士 `#ifndef/#define/#endif`：#include 是拷贝，重复包含 = 重复定义
- `-DDEBUG` 命令行定义宏 → `#ifdef DEBUG` 裁代码；`#if 0 ... #endif` 注释大段
- typedef 起类型别名真懂类型；`typedef int* p_t; p_t a,b;` 都是指针，#define 版 b 会变 int
- 函数指针：`int (*p)(int,int)`（*p 括号必须有，否则成函数声明）；typedef 后 `cmp_t` 清爽用；qsort 和内核驱动 ops 表的核心机制

## 内存布局速记（06）

- 五大区从低到高：**text → .data/.bss → 堆 → 映射区 → 栈**；堆向上长、栈向下长（递归验证过）
- **.data = 非零初始化全局/static（占文件体积）；.bss = "Better Save Space" = 未初始化/全零（不占文件）**；`= {0}` 会被 gcc 优化进 .bss，要看 .data 体积用 `= {1}`
- static 局部变量在**全局区**（.data/.bss），不在栈；字符串字面量在 .rodata（只读，写=段错误）；`char b[]="hi"` 是栈上拷贝（可改）
- 栈帧随函数调用/返回劈开/弹掉（不清零→垃圾值是残骸）；默认 8MB，大数组上栈=爆栈
- `return x;` 拷贝值合法；`return &x;` 返回栈地址=悬空指针。修法三选：返回值 / 出参指针 / static（或堆）
- malloc 未初始化（垃圾）；calloc 清零；realloc 扩；free(NULL) 安全
- 四大堆错误：泄漏 / 越界 / double free / UAF。口诀：**申请查 NULL，用完就 free，free 后置 NULL，不 free 栈地址**
- ASan：`gcc -g -fsanitize=address`；四种报错名：heap-buffer-overflow / double-free / heap-use-after-free / not-malloc()-ed；-Wall 也能静态提示 UAF 和 free 非堆地址

## 命令行速记（10）

- 目录地图：/etc 配置、/home 用户家、/var 变化数据(log)、/proc 内核假文件、/dev 设备文件（≠设备树！）、/usr 系统软件

## C++ 速记（C01）

- 引用 = 绑死的别名：必须初始化、不可换绑（`r = b` 是赋值不是改绑）、没有空引用；调用端比指针安全（语法上不可能传 NULL）
- 引用 vs 指针面试版：①指针可空 / 引用必须初始化 ②指针可换指向 / 引用绑死一个 ③指针可运算、有多级；引用都没有
- 重载：同名不同参；**返回类型不参与**（调用处无法区分）；匹配顺序：**精确 > 提升（float→double）> 转换**
- name mangling：C++ 符号名带参数类型（`_Z3addii` / `_Z3adddd`），C 就叫 `add`
- new/delete 配对：`new↔delete`、`new[]↔delete[]`；错配 = -Wall 静态警告 + ASan `alloc-dealloc-mismatch`
- 默认参数从右往左连续给；调用从左往右，不能跳空（`greet("Tom",,2)` 编译错）
- 头文件里不写 `using namespace`（污染所有包含它的文件）

## C++ 速记（C02）

- 构造/析构时机：出生→构造；出作用域 `}` / delete→析构；**顺序 = 构造的逆序**（后构造的先析构）
- 只写了带参构造 → 默认无参构造不再提供（`B b;` 编不过）；修法：补无参构造，或默认参数 `B(int x=0)`
- this = **当前对象的地址**（是指针！用 `this->x`），值 = 类外的 `&p`；`return *this` 支撑链式调用
- 拷贝构造三触发：① `T b = a;` ② 值传参 ③ 返回对象（③ 常被 **RVO** 消灭——返回值直接原地构造，C++17 保证）
- 浅拷贝（编译器默认版）= 指针成员共用同一块堆 → double free；深拷贝口述三步：**new 自己的 → strcpy 拷内容 → strlen 记得 +1**
- **三法则**：写了 析构/拷贝构造/operator= 中的一个，通常三个都得写；operator= 记得自赋值检查 `if (this == &other)`
- const 成员 / 引用成员**只能走初始化列表**（`: id(i), counter(c)`）——函数体开始时成员已出生：const 不能再赋值，引用不能再换绑
- 非 void 函数忘 return → -Wall 警告 + gcc 在函数尾插非法指令 → 运行 **Illegal instruction** 崩
- 同类成员函数可访问**同类其他对象**的私有成员（operator+ 里碰 a.x 合法）

## C++ 速记（C03）

- 基类**指针可以指向**派生类对象（不是"创建"！）；Dog 对象开头 = 完整的 Animal；反过来不行
- 非虚成员：按**指针静态类型**（编译期）决定调谁；virtual：按**对象实际类型**（运行期，经 vptr）——多态三件套：virtual + 重写 + 基类指针/引用调用
- vtable/vptr：每个有虚函数的类一张函数指针表；每个对象头 8 字节 = vptr。**同类对象 vptr 相同，不同类不同**（memcpy 头 8 字节可实测）
- 重写必加 override（拼错直接编译错，不加 = 静默变新函数、多态失效）
- 纯虚 `= 0` → 抽象类不能造对象（虚表格子空着，对象没法干活）；派生必须全部实现
- **虚析构**：基类指针 delete 派生对象，非虚只跑 ~Base → 泄漏；会被继承 + 经基类指针删除的类，析构必 virtual。机制：virtual 让 ~Derived 进虚表，运行期按实际类型找到并执行，C++ 保证再链到 ~Base
- 继承中顺序：构造 **基类 → 成员 → 自己函数体**；析构完全倒序（成员是 Derived 的零件，夹在中间）
- **构造函数不继承**：派生类自己写构造，初始化列表转交基类——`LedDevice(n) : Device(n) {}`；基类无默认构造而不转交 = 编译错（C02 Q4 坑的继承版）
- Itanium ABI 彩蛋：派生类成员可塞进**非 POD 基类的尾部 padding**（B=16 → C(+int y) 仍 16）
- 内核对应：抽象类/虚表 ≈ **file_operations**（C 的函数指针表 + 注册 + 框架按指针调用）
