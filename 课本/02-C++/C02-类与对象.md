# C02：类与对象

> C01 的伏笔在这课全部兑现：**new 会调用的"构造函数"、delete 会调用的"析构函数"**，到底是什么。
> 打法不变：一切对照 C。C 的 struct 只能打包**数据**；C++ 的 class 把**数据和操作数据的函数绑在一起**——这就是面向对象的第一块地基。

## 知识点 1：从 struct 到 class

先看 C 的痛点（你已经亲身写过）：

```c
// C：数据和操作是分离的，谁都能改 buf，函数要传 struct 指针
struct buffer { int *data; int size; };
void buf_init(struct buffer *b, int n);
void buf_destroy(struct buffer *b);
int  buf_get(struct buffer *b, int i);
```

C++ 把函数搬进类型里，并加上**访问控制**：

```cpp
class Buffer {
public:                          // 公开：外界可以用的接口
    void init(int n);
    void destroy();
    int  get(int i);
private:                         // 私有：只有类自己的函数能碰
    int *data;
    int  size;
};
```

- **public**：对外接口；**private**：内部实现，外界碰了**直接编译错**
- 这就是**封装**：数据藏在里面，只留方法操作它。"谁能改 data"从"靠自觉"变成"编译器强制"
- `class` 和 `struct` 在 C++ 里**几乎一样**，唯一区别：class 默认 private，struct 默认 public。习惯：当"类"用写 class，只想打包数据写 struct

```cpp
Buffer b;
b.data;        // ❌ 编译错：private——保护生效
b.init(10);    // ✅ 只能走公开接口
```

> 驱动视角：Linux 内核是纯 C，靠"把 struct 和函数指针表绑一起"模拟这套封装（05 课的 ops 表 + 05 课函数指针）——学完你再看内核代码会看懂它的"人肉面向对象"。

## 知识点 2：构造函数——出生自动执行的代码

**构造函数**：与类同名、**没有返回值类型**、对象创建时**自动调用**。用来保证"对象一出生就是好的"（C 里 malloc 完忘了初始化的 bug，从根上消灭）。

```cpp
#include <cstdio>

class Buffer {
public:
    Buffer(int n) {                  // 构造函数（带参）
        data = new int[n]{};         // 出生就分配+清零
        size = n;
        std::printf("构造 %d 个\n", n);
    }
    int get(int i) { return data[i]; }
    ~Buffer();                       // 先声明，见知识点3
private:
    int *data;
    int  size;
};

int main() {
    Buffer b(10);        // 栈上对象：定义即构造，打印"构造 10 个"
    Buffer *p = new Buffer(5);   // 堆上对象：new 调用构造 —— C01 伏笔兑现
    std::printf("%d\n", b.get(3));
    delete p;            // delete 调用析构
    return 0;
}                        // main 结束，b 离开作用域 → 自动析构（不用你管！）
```

要点：

1. **构造函数可以重载**（C01 的重载在这里落地）：无参 / 带参 / 拷贝构造（知识点5）可以共存
2. 你没写任何构造函数时，编译器送你一个**默认构造**（无参、啥也不干）；但你一旦写了带参的，默认构造就**不再自动提供**——`Buffer b;` 会编译错
3. 栈对象离开 `{}` 自动析构、堆对象 delete 才析构——**生命周期决定析构时机**（06 课的栈堆知识直接平移过来）

## 知识点 3：析构函数——死亡自动执行的代码

**析构函数**：`~类名`、无参数无返回值、对象销毁时**自动调用**。用来释放资源（new 的内存、打开的文件……）。

```cpp
Buffer::~Buffer() {
    std::printf("析构，释放 %d 个\n", size);
    delete[] data;             // 呼应 C01：new[] 配 delete[]
}
```

**析构顺序**（笔试爱考）：

- 栈对象：**后构造的先析构**（和栈帧弹出顺序一致——想想 06 课递归的回弹）
- `new[]` 一排对象：按下标 **0 → n-1** 逐个析构再释放内存
- 全局对象：main 结束后析构

**为什么析构重要（一句话）**：有了"死亡自动执行代码"的保证，资源释放就不依赖程序员的记性——这个思想叫 **RAII**（C05 细讲，智能指针的地基）。你 06 课背的口诀"用完就 free"从此可以升级成"把 free 写进析构，让编译器替你记"。

## 知识点 4：this 指针——成员函数的隐藏参数

```cpp
b.get(3);
```

编译器眼里的真面目（伪代码）：

```cpp
get(&b, 3);      // 对象地址被偷偷当作第一个参数传入
```

成员函数里访问这个隐藏参数的关键字就是 **this**——指向**当前对象**的指针：

```cpp
class Point {
public:
    void setX(int x) { this->x = x; }   // 参数名和成员名撞了？this-> 区分
private:
    int x;
};
```

三个必知：

1. `this` 的类型是 `Point*`（const 成员函数里是 `const Point*`）
2. **成员名和参数名撞车时**，`this->x` 指成员、裸 `x` 指参数——常见的救命写法；当然更好的习惯是起不同的名字
3. `return *this;` 返回对象自身——链式调用的基础（`a.f().g().h()`）

> 本质：**C++ 的成员函数就是编译器帮你传了 this 的普通函数**。C 里手写过 `void buf_init(struct buffer *b, ...)` 吗？那个 `b` 就是人肉 this。内核 C 代码里满屏的 `container_of` 本质也是"从成员找 this"。

## 知识点 5：拷贝构造 + 浅拷贝/深拷贝 ⭐ 笔试钉子户

**拷贝构造函数**：参数是"自身类型的引用"的构造——**用一个旧对象构造新对象**时调用：

```cpp
Buffer(const Buffer& other);      // 标准形态：const 引用
```

三个触发时刻（笔试常考，背下来）：

```cpp
Buffer b2 = b1;      // ① 用 b1 定义 b2
func(b1);            // ② 值传参（拷贝一份进函数）
return b1;           // ③ 值返回（拷贝一份出去）
```

你没写时编译器送一个**默认拷贝构造**——但它只会**逐成员原样复制**（memcpy 语义）。指针成员一复制，**灾难开始**：

### 浅拷贝翻车现场（本课最重要的一段）

```cpp
Buffer a(10);
Buffer b = a;        // 默认拷贝构造：b.data = a.data —— 两个对象指向同一块堆内存！
// main 结束：a 析构 delete[] data；b 析构又 delete[] 同一块 → double free！
```

用 ASan 跑就是 06 课抓过的 `attempting double-free`。**浅拷贝 = 只抄地址不抄内容**；**深拷贝 = 自己再 new 一块，把内容抄过来**：

```cpp
Buffer::Buffer(const Buffer& other) {
    size = other.size;
    data = new int[size];              // 自己的内存
    for (int i = 0; i < size; i++)     // 内容抄过来
        data[i] = other.data[i];
}
```

**面试标准问答**：「默认拷贝构造是浅拷贝；成员含指针时，两个对象会共享一块资源，析构时 double free、修改时互相干扰。需要自己写拷贝构造做深拷贝。」（进阶：还有"拷贝赋值 operator=" 同样要处理——考点同名，先知道）

> 这就是 C 里 `struct A b = a;` 含指针成员时的同款坑，只是 C++ 给了让你**自定义复制行为**的入口。06 课的堆错误知识 + ASan 工具在这里全部复用。

## 知识点 6：运算符重载——让对象能用 + 和 <<

C 的痛点：两个复数/两个矩阵相加，只能写 `add(a, b)`，不能写 `a + b`。C++ 允许给**自己的类型**重新定义运算符含义：

```cpp
class Complex {
public:
    Complex(double r, double i) : re(r), im(i) {}     // 知识点7 的初始化列表写法
    double re, im;
};

Complex operator+(const Complex& a, const Complex& b) {   // 重载 +
    return Complex(a.re + b.re, a.im + b.im);
}

int main() {
    Complex x(1, 2), y(3, 4);
    Complex z = x + y;        // 编译器翻译成 operator+(x, y)
    std::printf("%g+%gi\n", z.re, z.im);   // 4+6i
}
```

- 本质：`x + y` 只是 `operator+(x, y)` 的**语法糖**——又一个"糖衣"概念（引用也是，C01）
- 规则：不能发明新运算符、不能改变对 int 等内置类型的含义、`=` `[]` `()` `->` 只能写成成员函数（先知道）
- C01 里 `std::cout << "x=" << x` 能连着写，就是标准库重载了 `operator<<` 返回 cout 自身（`return *this` 的链式调用——知识点4 闭环）

## 知识点 7：初始化列表——构造函数的"正规"写法

```cpp
class Buf {
public:
    Buf(int n) : size(n), data(new int[n]{}) {}   // 冒号后面就是初始化列表
private:
    const int size;      // const 成员 / 引用成员，只能在这初始化
    int *data;
};
```

- 语法：构造函数 `:` 后跟 `成员(值)` 逗号分隔，在 `{` **之前**完成初始化
- 为什么用它：① const 成员和引用成员**只能**在列表初始化（函数体里赋值=先初始化再赋值，const 不允许二次赋值）② 少一次默认构造+赋值的开销 ③ 成员初始化顺序 = **声明顺序**，不是列表顺序（坑）
- 工程习惯：能写列表就写列表。看到 `: size(n)` 别陌生——开源 C++ 代码里到处是

## 综合示例：一页纸串起 7 个知识点

```cpp
#include <cstdio>

class Stack {
public:
    Stack(int cap) : cap_(cap), data_(new int[cap]{}), top_(0) {   // 7 初始化列表
        std::printf("构造 cap=%d\n", cap);
    }
    Stack(const Stack& o) : cap_(o.cap_), data_(new int[o.cap_]), top_(o.top_) {  // 5 深拷贝
        for (int i = 0; i < top_; i++) data_[i] = o.data_[i];
        std::printf("拷贝构造（深）\n");
    }
    ~Stack() {                                                       // 3 析构
        std::printf("析构 top=%d\n", top_);
        delete[] data_;
    }
    void push(int v) { data_[top_++] = v; }
    int  top() const { return data_[top_ - 1]; }                     // const 成员函数：承诺不改对象
    Stack& operator<<(int v) { push(v); return *this; }              // 6 运算符重载 + 4 this 链式
private:                                                             // 1 封装
    int cap_;
    int *data_;
    int top_;
};

int main() {
    Stack s(8);          // 2 构造
    s << 10 << 20 << 30; // 链式 push（运算符重载 + return *this）
    Stack t = s;         // 拷贝构造（深）
    std::printf("top=%d\n", t.top());
    return 0;
}                       // t 先析构、s 后析构（后构造的先死）
```

**先预测打印顺序**（构造/拷贝/top/两个析构的顺序），再跑。
