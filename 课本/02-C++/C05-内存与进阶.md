## 知识点 1：RAII——你在 C02 已经写过了

**RAII** = Resource Acquisition Is Initialization（资源获取即初始化）。定义土话版：

> 把资源（堆内存 / 文件 / 锁 / socket）的生死绑在对象的生死上：**构造函数拿资源，析构函数还资源**。对象出作用域，编译器保证调析构——资源一定被还。

你已经会了，因为 C02 的 IntArray 就是标准 RAII：

```cpp
{
    IntArray a(10);   // 构造：new（拿）
    ...
}                     // 出作用域：~IntArray 自动调（还）——不管中间几个 return
```

RAII 真正的杀手锏是**出错路径也安全**：函数中途 return、甚至抛异常（见知识点 4），栈上对象的析构照样执行——C 的 malloc/free 做不到这一点（提前 return = 泄漏）。

面试话术：「RAII 把资源生命周期绑定到对象生命周期，利用析构函数自动释放资源，即使异常路径也不泄漏；智能指针、lock_guard 都是 RAII 的应用。」

## 知识点 2：unique_ptr——独占式智能指针

IntArray 那 40 行管理代码，标准库一行替你写完了：

```cpp
#include <memory>
#include <cstdio>

int main() {
    std::unique_ptr<int> p = std::make_unique<int>(42);   // 推荐 make_unique，不写裸 new
    std::printf("%d\n", *p);                              // 用法和指针一样：*p、p->

    // std::unique_ptr<int> q = p;          // ❌ 编译错：unique_ptr 独占，禁止拷贝
    std::unique_ptr<int> q = std::move(p);  // ✅ 只能"转移所有权"：p 变空，q 接管
    if (!p) std::printf("p 已经交出去了\n");
    return 0;
}                                          // q 出作用域自动 delete——全程零 delete
```

- **同一块内存永远只有一个主人**：不能拷贝（编译错替你把 double free 拍死在编译期），要换主人只能 `std::move` 明写
- 数组版：`std::unique_ptr<int[]> arr(new int[5]{});`，用 `arr[i]`——不过定长数组首选 vector，这个形态主要用于 C 接口给的裸内存
- C02 三法则那 40 行（析构+拷贝构造+operator=）在这里**一行都不用写**

## 知识点 3：shared_ptr / weak_ptr——共享与循环引用 ⭐ 面试高频

资源确实需要"好几个地方一起用"时，用 shared_ptr：**引用计数**——每多一个shared_ptr 指着，计数 +1；计数归零才 delete。

```cpp
auto a = std::make_shared<int>(10);   // 计数 1
{
    auto b = a;                       // 拷贝：计数 2
    std::printf("%ld %ld\n", a.use_count(), b.use_count());   // 2 2
}                                     // b 出作用域：计数 1
std::printf("%ld\n", a.use_count());  // 1
```

**循环引用——shared_ptr 唯一的大坑（必考）**：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::printf("~Node\n"); }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;      // b 的计数 = 2（b 自己 + a）
b->next = a;      // a 的计数 = 2（a 自己 + b）
// main 结束：a、b 出作用域，各把对方计数减 1 → 都是 1，永远到不了 0
// 💥 ~Node 一次都不跑，两个 Node 泄漏——引用计数救不了环
```

**修法：环上一边改 `weak_ptr`**（"我认识你，但不拥有你"）：

```cpp
struct Node {
    std::weak_ptr<Node> next;                    // 弱引用：不增加计数
    ...
};
a->next = b;                                     // b 计数不变
// 要用的时候 upgrade：std::shared_ptr<Node> t = a->next.lock();
```

面试话术：「shared_ptr 靠引用计数共享所有权，计满归零释放；相互引用会成环导致计数永不归零，用 weak_ptr 打破环，使用时 lock() 提升。」

## 知识点 4：异常——出错路径的统一出口

```cpp
#include <stdexcept>

double div(int a, int b) {
    if (b == 0) throw std::runtime_error("div by zero");   // 抛
    return (double)a / b;
}

try {
    div(1, 0);
} catch (const std::exception& e) {          // 按基类引用接（C03 的多态！）
    std::printf("抓到了: %s\n", e.what());
}
```

- throw 后，函数**就地终止**，沿调用链往外找 catch——沿途栈上对象的析构**照样执行**（栈展开 stack unwinding）。这就是 RAII 和异常是绝配的原因：出错也不漏资源
- 你已经见过一次：C04 的 `v.at(越界)` 抛 `std::out_of_range`
- ⚠️ 澄清一个误区：**整数除零是 UB，不是异常**——不会抛、别指望 catch 住（浮点除零得 inf）
- **构造函数失败只能靠 throw**：构造没有返回值，没地方报错（这是异常最不可替代的用途）
- 嵌入式视角：实时系统/内核驱动**禁用异常**（`-fno-exceptions`，异常的栈展开时间不可预测）——所以"会用 + 知道什么时候不用"都要会答

## 知识点 5：lambda——匿名函数

C04 的 sort 比较器要"到别处写个函数再传进来"，lambda 让你**就地写**：

```cpp
auto add = [](int a, int b) { return a + b; };    // [捕获](参数) { 函数体 }
std::printf("%d\n", add(3, 4));                   // 7

int base = 100;
auto f1 = [base](int x) { return base + x; };     // 值捕获：拷一份 base 进来
auto f2 = [&base](int x) { base += x; };          // 引用捕获：动外面的原件
f1(1);                       // 101，base 还是 100
f2(1);                       // base 变 101

std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // 降序一行搞定
```

- `[]` 捕获列表：`[]` 不捕、`[x]` 值捕、`[&x]` 引用捕、`[=]`/`[&]` 全捕（慎用）
- 本质：编译器替你生成一个匿名类，`operator()` 就是函数体（值捕获=成员拷贝，引用捕获=成员引用）——又是"编译器替你写代码"
- ⚠️ 坑：**引用捕获局部变量 + lambda 活得比变量久 = 悬空**（出了作用域还在用）——捕获默认写值捕获，明确要改原件才用 `&`

## 知识点 6：三课合流——`vector<unique_ptr<Shape>>`

C03 的多态 + C04 的容器 + C05 的所有权，一套代码合流（现代 C++ 项目里最常见的形态）：

```cpp
#include <memory>
#include <vector>
#include <cstdio>

class Shape {
public:
    virtual void speak() = 0;
    virtual ~Shape() {}
};
class Dog : public Shape {
public:
    void speak() override { std::printf("汪!\n"); }
};
class Cat : public Shape {
public:
    void speak() override { std::printf("喵~\n"); }
};

std::unique_ptr<Shape> make_dog() { return std::make_unique<Dog>(); }   // 工厂函数

int main() {
    std::vector<std::unique_ptr<Shape>> zoo;
    zoo.push_back(make_dog());
    zoo.push_back(std::make_unique<Cat>());

    for (const auto& s : zoo)      // 注意 auto&：unique_ptr 不能拷，必须引用
        s->speak();                // 多态：虚表跳转（C03）

    return 0;
}   // zoo 销毁 → 每个 unique_ptr 各自 delete → 虚析构兜底（C03）→ 零 delete、零泄漏
```

看懂这段，C++ 阶段的三大件（生命周期/多态/容器）就焊在一起了。

## 知识点 7：内存武器库全景（选型表）

| 场景 | 用什么 | 一句话 |
|------|--------|--------|
| 定长小数据 | 栈 / C 数组 | 最快，免费 |
| 动态数组 | **vector** | 默认首选 |
| 单个对象，作用域内独占 | **unique_ptr** | 零开销、防拷贝 |
| 多处共享同一对象 | **shared_ptr** | 计数有开销，警惕循环引用 |
| 对接 C 接口 / 自定义释放动作 | unique_ptr + deleter（进阶，先知道） | fclose/free 包装 |
| 裸 new/delete | **基本不再写** | 写了要能说出理由 |

## 综合示例：出错也不漏（一页串 RAII + 异常）

```cpp
#include <cstdio>
#include <stdexcept>
#include <memory>

struct Guard {
    const char* name;
    Guard(const char* n)  : name(n) { std::printf("%s: 拿资源\n", name); }
    ~Guard()              { std::printf("%s: 还资源\n", name); }
};

void work(bool fail) {
    Guard g1("g1");
    if (fail) throw std::runtime_error("中途出错");
    Guard g2("g2");
}

int main() {
    try {
        work(true);
    } catch (const std::exception& e) {
        std::printf("main 抓到: %s\n", e.what());
    }
    return 0;
}
```

**先预测**：g2 的"拿资源"会出现吗？g1 的"还资源"呢？（throw 之后 g1 照样析构——RAII 的杀手锏。）
