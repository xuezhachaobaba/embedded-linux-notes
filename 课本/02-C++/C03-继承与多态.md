## 知识点 1：继承——代码复用的"家族树"

C 的痛点：写好 `Animal`（有名字、会吃），再写 `Dog`、`Cat` 时名字和吃的逻辑得抄一遍。C++ 让类**继承**另一个类：

```cpp
class Animal {
public:
    Animal(const char* n) : name(n) {}
    void eat() { std::printf("%s 在吃\n", name); }
protected:
    const char* name;      // protected：自己和派生类能碰，外界不能
};

class Dog : public Animal {           // Dog 继承 Animal
public:
    Dog(const char* n) : Animal(n) {} // 构造时先把基类部分造好
    void bark() { std::printf("%s 汪汪\n", name); }   // 直接用基类的 name
};
```

- `class Dog : public Animal` 读作"Dog **是一个** Animal"（**is-a** 关系）。继承的前提是 is-a 成立——"狗是一个动物"✅；"车有一个引擎"是 has-a，那该用**成员**而不是继承
- Dog 自动获得 Animal 的全部成员，还加上自己的 `bark`
- 访问级别补一刀：**public** 谁都能碰 / **protected** 自己+儿子能碰 / **private** 只有自己（C02 学了两个，现在补全）
- 继承 ≠ 万能：组合（成员）往往比继承更灵活——先记一句"优先组合，必要时继承"

## 知识点 2：基类指针指向派生类对象——一切的核心前提

这行代码是整个多态的钥匙，先把它焊死：

```cpp
Animal* p = new Dog("旺财");     // ✅ 基类指针指向派生类对象
```

**为什么合法**：Dog 是一个 Animal（is-a），所以"指向 Animal 的指针"指向一只狗天经地义——就像"`int*` 能指向 int 数组的开头"，类型兼容的自然延伸。反过来 `Dog* p = new Animal(...)` **不行**（动物不一定是狗）。

内存视角（04/06 课技能复用）：**Dog 对象开头就是一段完整的 Animal**（基类子对象在前），所以 `Animal*` 拿它当 Animal 用毫无问题——指针类型决定"怎么看这块内存"，这是 02b 课的老知识。

```cpp
Animal* p = new Dog("旺财");
p->eat();      // ✅ Animal 有的，肯定能调
p->bark();     // ❌ 编译错：Animal 眼里没有 bark
```

问题来了：如果 Dog 重写了 eat（狗吃饭有自己的姿势），`p->eat()` 调谁的版本？——这就是知识点 3。

## 知识点 3：虚函数与多态——同一个调用，不同的行为

```cpp
class Animal {
public:
    virtual void speak() { std::printf("%s: ...\n", name); }   // ← 加 virtual
    ...
};
class Dog : public Animal {
public:
    void speak() { std::printf("%s: 汪汪!\n", name); }          // 重写（签名一致）
};
class Cat : public Animal {
public:
    void speak() { std::printf("%s: 喵~\n", name); }
};

void make_sound(Animal* a) {     // 一个函数，接收任何动物
    a->speak();                  // 运行时才决定调谁——多态！
}

make_sound(new Dog("旺财"));     // 旺财: 汪汪!
make_sound(new Cat("咪咪"));     // 咪咪: 喵~
```

- **virtual** 只需要写在**基类**声明里（派生类里写不写都算重写，规范是也写上 virtual）
- 没加 virtual：`p->speak()` 按**指针类型**（编译期）决定 → 调 Animal 版
- 加了 virtual：`p->speak()` 按**对象实际类型**（运行期）决定 → 调 Dog/Cat 版。这个"运行期才定"的机制叫**动态绑定/晚绑定**
- **多态 = 同一个调用 `a->speak()`，随对象不同表现出不同行为**。前提三件套：① virtual ② 重写 ③ 基类指针/引用调用

**为什么这东西值钱**：`make_sound` 这段代码写完后，以后新增 `Duck` 类，**make_sound 一行不改**就能嘎嘎叫——"对扩展开放，对修改关闭"。C 里要实现同样效果得手写函数指针表（你 05 课学的 cmp_t、内核的 file_operations 都是这么干的——**C++ 的 virtual 就是编译器替你维护的函数指针表**，见下）。

## 知识点 4：虚表——内存层面看多态（结合 04/06 课）

virtual 的底层实现（面试高频，答出来直接上一个档位）：

1. 有虚函数的类，编译器给它配一张**函数指针数组**，叫**虚表（vtable）**——每个虚函数占一格，存的是"该类实际要执行的函数地址"
2. 每个对象开头藏一个指针 **vptr**，指向自己类的虚表（所以 05 课的函数指针是这里的砖）
3. `a->speak()` 的真实执行：`a->vptr -> vtable[第i格] -> 调用`——**多一次指针跳转**，这就是动态绑定的代价（很小，但面试爱问）

```
Dog 对象 "旺财"                Dog 的虚表 vtable
┌─────────────┐               ┌──────────────────┐
│ vptr ────────┼──────────────►│ speak → Dog::speak │
│ name        │               └──────────────────┘
└─────────────┘
Cat 对象同理，vptr 指向 Cat 的表（speak → Cat::speak）
```

**眼见为实（跑这个）**：

```cpp
#include <cstdio>
class A { int x; };                       // 无虚函数
class B { virtual void f() {} int x; };   // 有虚函数

int main() {
    std::printf("A: %zu\n", sizeof(A));   // 4  ——就一个 int
    std::printf("B: %zu\n", sizeof(B));   // 16 ——x(4)+padding(4)+vptr(8)！凭空多 8 字节
    return 0;
}
```

**vptr 是 8 字节指针（64 位），藏在对象头**——04 课的对齐知识解释了为什么是 16 不是 12（int 4 + padding 4 凑 8 的倍数给 vptr 让位）。想再狠一点：用 04 课的逐字节打印看对象内存，头 8 字节就是 vptr 的值（两张不同类的对象，头 8 字节不同；同类对象相同）。

## 知识点 5：override——重写的"合同检查"

重写的规则：**函数名、参数列表、const、返回类型**都要和基类虚函数一致（返回类型允许是基类返回类型的指针/引用，先不管）。

写重写时养成习惯加 **override** 关键字（C++11）：

```cpp
class Dog : public Animal {
public:
    void speak() override { ... }   // ✅ 显式声明"我在重写"
    // void speek() override        // ❌ 拼错 → 编译器直接报错：没有可重写的基类函数
};
```

不加 override 时，`speek` 拼错只是**默默变成一个新函数**（多态悄悄失效，调用的还是基类版）——最难查的那类 bug。加了 override，编译器替你核对签名。**原则：写重写必加 override**（同 `-Wall`、`-fsanitize` 一个思想：把错误拦在编译期）。

## 知识点 6：纯虚函数与抽象类——"定接口，不定实现"

```cpp
class Shape {
public:
    virtual double area() const = 0;    // = 0：纯虚函数——只声明接口，不给默认实现
    virtual ~Shape() {}                 // 见知识点7，先埋个伏笔
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
};

class Rect : public Shape {
    double w, h;
public:
    Rect(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
};

double total(Shape** shapes, int n) {       // 只依赖接口
    double s = 0;
    for (int i = 0; i < n; i++) s += shapes[i]->area();
    return s;
}
```

- 含纯虚函数的类 = **抽象类**：**不能创建对象**（`new Shape` 编译错）——"面积"对抽象的"形状"根本没有意义，禁止很合理
- 派生类**必须**实现所有纯虚函数，否则它自己也是抽象类
- 抽象类 = **接口契约**：规定"想当 Shape，就得会 area()"。`total()` 只面向契约编程，新增三角形不用改它
- 驱动对照：内核里"每种设备都必须实现 open/read/write/ioctl"就是一套纯虚接口思想——C 没语法，靠 file_operations 结构体（函数指针表）+ 约定实现。**抽象类 ≈ 编译器帮你查合同 的函数指针表**

## 知识点 7：虚析构——基类析构必须是 virtual ⭐ 经典必考

**先看事故（跑一下，加 -fsanitize=address）**：

```cpp
class Base {
public:
    Base()  { std::printf("Base 构造\n"); }
    ~Base() { std::printf("Base 析构\n"); }        // ❌ 没加 virtual
};
class Derived : public Base {
    int* data;
public:
    Derived()  : data(new int[100]) { std::printf("Derived 构造\n"); }
    ~Derived() { delete[] data; std::printf("Derived 析构\n"); }
};

int main() {
    Base* p = new Derived();   // 基类指针 + 派生类对象（知识点2，日常写法）
    delete p;                  // 💥 只调了 ~Base！Derived::data 泄漏 400 字节
}
```

输出只有"Base 构造 / Base 构造"……不对，是"Base 构造、Derived 构造、**Base 析构**"——**~Derived 没被调用**，`data` 的 400 字节直接泄漏（ASan 报 `100 byte(s) leaked` 那套，06 课的老朋友）。

**原因**：析构函数不是 virtual 时，`delete p` 按**指针类型**（Base）静态决定调 ~Base——派生类的清理代码被整个跳过。

**修法（一句话背死）**：

```cpp
class Base {
public:
    virtual ~Base() { ... }    // ✅ 只要这个类会被继承、且会通过基类指针 delete
};
```

析构一变虚，`delete p` 就按**对象实际类型**走：先 ~Derived（释放 data）再 ~Base（C++ 保证顺序）——多态机制在析构上的同款应用。

**面试话术**：「基类析构函数若不是 virtual，通过基类指针 delete 派生类对象时，派生类析构不会被调用，造成资源泄漏；所以**作为基类使用的类析构函数应声明为 virtual**。」

## 知识点 8：继承中的构造/析构顺序（笔试爱考）

```cpp
Derived d;
```

- **构造顺序**：基类构造 → 成员构造 → 派生类构造函数体（"先造地基再盖楼"——爹的成员得先就位，儿子的函数体才能安全用它们）
- **析构顺序**：**完全反过来**：派生类析构 → 成员析构 → 基类析构（"先拆楼再拆地基"）

```cpp
Base* p = new Derived();
delete p;      // （虚析构时）~Derived → ~Base
```

对照 06 课：栈上对象"后构造的先析构"是**兄弟之间**的顺序；这里是**单个对象内部**父子层的顺序。两个规则不冲突，各管一层。

## 综合示例：一页串起本课

```cpp
#include <cstdio>

class Shape {
public:
    Shape() { std::printf("Shape 构造\n"); }
    virtual double area() const = 0;          // 纯虚：接口
    virtual ~Shape() { std::printf("Shape 析构\n"); }   // 虚析构：保命
};

class Rect : public Shape {
    double w, h;
public:
    Rect(double w, double h) : w(w), h(h) { std::printf("Rect 构造\n"); }
    double area() const override { return w * h; }
    ~Rect() { std::printf("Rect 析构\n"); }
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) { std::printf("Circle 构造\n"); }
    double area() const override { return 3.14159 * r * r; }
    ~Circle() { std::printf("Circle 析构\n"); }
};

int main() {
    Shape* arr[] = { new Rect(2, 3), new Circle(1) };   // 基类指针数组（知识点2）
    double total = 0;
    for (Shape* s : arr) total += s->area();            // 多态（知识点3）
    std::printf("total = %g\n", total);
    for (Shape* s : arr) delete s;                      // 虚析构兜底（知识点7）
    return 0;
}
```

**先预测 8 行输出的顺序**（Shape构造→Rect构造→Shape构造→Circle构造→total→Rect析构→Shape析构→Circle析构→Shape析构——等等，数一数到底几行），再跑。
