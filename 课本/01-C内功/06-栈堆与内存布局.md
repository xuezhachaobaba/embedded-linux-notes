## 知识点 1：进程内存布局——五大区（画图题）

一个 C 程序跑起来（成为进程），它的虚拟地址空间从**低地址到高地址**分成五大区：

```
高地址 ┌──────────────────┐
       │   栈 (stack)      │ ↓ 向下生长
       │      ...          │
       │   内存映射区       │ （动态库、mmap）
       │      ...          │
       │   堆 (heap)       │ ↑ 向上生长
       ├──────────────────┤
       │  .bss  未初始化全局/静态  （不占文件体积）
       │  .data 已初始化全局/静态  （占文件体积）
       │  .text  代码（只读）      │
低地址 └──────────────────┘
```

**背法**："**代码 → 数据 → 堆 → 映射 → 栈，从低往高；堆向上长，栈向下长**"。

### 眼见为实（跑这个）

```c
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;        // .data（已初始化全局）
int g_uninit;           // .bss（未初始化全局）
static int s_v = 7;     // .data（静态也算全局区）

int main(void) {
    int local = 1;                  // 栈
    static int s_local = 2;         // .data（static 局部变量也在全局区！）
    int *heap = malloc(100);        // 堆
    char *str = "hello";            // 字符串字面量在常量区（.rodata）

    printf("代码区   text:    %p\n", (void*)main);
    printf("已初始化 .data:   %p\n", (void*)&g_init);
    printf("未初始化 .bss:    %p\n", (void*)&g_uninit);
    printf("堆      heap:     %p\n", (void*)heap);
    printf("栈      stack:    %p\n", (void*)&local);
    printf("常量区   rodata:  %p\n", (void*)str);
    free(heap);
    return 0;
}
```

**先预测各地址的相对高低，再跑**。你会看到：main < g_init ≈ g_uninit < heap < local（低→高），完全符合布局图。

> static 局部变量在**全局区**不在栈上——它活得和程序一样长（03 课"静态存储区"的真身）。malloc 的地址可能落进"内存映射区"，也算堆分配，正常。

## 知识点 2：栈——自动管理的"函数工作台"

**栈管函数调用**：每次调用函数，就在栈上劈一块空间叫**栈帧**，装这个函数的局部变量、参数、返回地址。函数一返回，栈帧**整个弹掉**（只移动栈指针，极快，不清零——所以垃圾值能"读到上一次的残骸"）。

```c
void foo(void) {
    int a = 1, b = 2;    // a、b 在 foo 的栈帧里
}                        // foo 返回 → 栈帧弹掉，a、b 的内存"作废"（值还在，但已不属于任何人）
```

特点：
- **自动**：进函数分配、出函数回收，不用你管
- **快**：移动一个指针的事
- **小**：Linux 默认每线程 **8 MB**（`ulimit -s` 可查）。大数组放栈上会爆——`int a[10*1024*1024]`（40MB）直接段错误
- 局部数组初始化 `{0}` 的成本、变长数组 VLA 都是栈上操作，注意大小

**验证栈向下生长**：

```c
void inner(int depth) {
    int x;
    printf("depth %d: %p\n", depth, (void*)&x);
    if (depth > 0) inner(depth - 1);   // 递归：每层的 x 地址越来越低
}
```

## 知识点 3：返回局部变量地址 = 经典炸弹（必考找错）

```c
int* get_num(void) {
    int x = 42;
    return &x;            // ❌ 返回栈上变量的地址
}

int main(void) {
    int *p = get_num();
    printf("%d\n", *p);   // 未定义行为！可能打出 42（残骸还在），也可能打出垃圾，也可能崩
    return 0;
}
```

**为什么错**：get_num 返回瞬间，它的栈帧弹掉，`x` 的地址还在 p 手里，但那块内存**已作废**——下次任何函数调用都会复用那块栈。`*p` 读到什么是运气。

**这是"悬空指针"（dangling pointer）的标准产地**。三种合法替代：

```c
// ① 返回值（拷贝走）
int get_num(void) { int x = 42; return x; }

// ② 调用者给内存（出参）
void get_num(int *out) { *out = 42; }

// ③ 静态/堆（活得久）
int* get_num(void) { static int x = 42; return &x; }   // 或 malloc
```

> ⚠️ 常见误解修正：**"返回局部变量"本身没错，错的是"返回局部变量的地址"**。`return x;` 拷贝值走，安全；`return &x;` 才是炸弹。

## 知识点 4：堆——你管的"自由市场"

堆给你**按需申请、活得不受函数限制**的内存。C 里用 `malloc` 家族（`<stdlib.h>`）：

```c
int *p = malloc(10 * sizeof(int));   // 申请 40 字节，返回 void*（不初始化，内容是垃圾）
if (p == NULL) { /* 申请失败必须检查 */ }
for (int i = 0; i < 10; i++) p[i] = i * 10;
free(p);                             // 用完必须还，否则泄漏
p = NULL;                            // 好习惯：free 后置 NULL，防止悬空
```

家族成员：

| 函数 | 行为 |
|------|------|
| `malloc(n)` | 要 n 字节，**内容不初始化**（垃圾） |
| `calloc(10, 4)` | 要 10×4 字节，**清零** |
| `realloc(p, n)` | 把 p 指向的块改成 n 字节（可能搬家，返回新地址） |
| `free(p)` | 还内存。`free(NULL)` 安全无害 |

要点：
- **malloc 返回 `void*`**，C 里自动转任何指针类型（C++ 里必须强转——以后对照）
- **失败返回 NULL**，大块申请必须检查
- malloc 100 字节 ≠ 后面有 100 字节可用：**越界写堆会破坏堆管理结构**，症状是"在很远的 free 处崩"（最难调的 bug 之一）
- 堆上有元数据（记录块大小），所以 free 知道还多少——这就是为什么 **free 一个栈地址/野指针会崩**：它把元数据读花了

## 知识点 5：四大堆错误 + 内存泄漏（高频）

**① 泄漏（leak）**：malloc 了不 free，函数返回指针一丢，那块内存到进程结束都拿不回来。

```c
void leak(void) {
    int *p = malloc(100);
    // 没 free 就返回 → 100 字节永久丢失
}
```

短命程序泄漏无感（进程结束 OS 全收走），但**守护进程/服务器**天天漏 → 内存耗尽。嵌入式设备常年不重启，泄漏 = 定时炸弹。工具：`valgrind ./a.out` 或编译加 `-fsanitize=address`（都装一下，作业要用）。

**② 越界（heap overflow）**：

```c
int *p = malloc(10 * sizeof(int));
p[10] = 1;      // ❌ 下标 10 已越界（合法 0~9），破坏堆元数据，可能在 free 时崩
```

**③ 双重释放（double free）**：

```c
free(p);
free(p);        // ❌ 同一块还两次 → 堆结构破坏，glibc 报 "double free detected"
```

**④ 释放后使用（use-after-free）/ 野指针**：

```c
free(p);
*p = 10;        // ❌ p 成了悬空指针，写的不是你的内存
```

**四连防护口诀**：**申请查 NULL，用完就 free，free 后置 NULL，不 free 栈地址**。

## 知识点 6：栈 vs 堆——面试一句话版

| | 栈 | 堆 |
|---|---|---|
| 谁管 | 编译器/系统**自动** | **你**手动（malloc/free） |
| 速度 | 快（移指针） | 慢（找空闲块+记账） |
| 大小 | 小（~8MB，会爆） | 大（受物理内存/虚拟内存限制） |
| 生命周期 | 随函数生灭 | free 前一直活着，跨函数 |
| 典型错误 | 爆栈、返回局部变量地址 | 泄漏、越界、double free、UAF |
| 生长方向 | 向下 | 向上 |

**面试一句话**："栈由系统自动分配回收、快但小，管函数局部变量；堆由程序员手动管理、慢但大，生命周期自由，代价是要防泄漏和悬空。"

## 知识点 7：全局区细节（.data / .bss）+ 常量区

- **.data**：**已初始化**的全局/static 变量，值存在可执行文件里（占体积）
- **.bss**：**未初始化**（或初始化为 0）的全局/static 变量，**不占文件体积**——文件里只记"需要多少字节的全 0"，加载时清零。嵌入式瘦身上有用：大缓冲区写 `int buf[N];` 全局放着，比 `= {0}` 初始化省 flash
- **常量区（.rodata）**：字符串字面量 `"hello"`、`const` 全局变量——**只读**，往里写 = 段错误

```c
char *a = "hello";   // a 在栈，"hello" 在 .rodata
a[0] = 'H';          // ❌ 段错误！写只读区
char b[] = "hello";  // b 是栈上数组，把 "hello" 拷了进来
b[0] = 'H';          // ✅ 合法
```

这个对比是笔试常客：**指针指向常量区（不可改）vs 数组自己持有拷贝（可改）**。

**验证 .bss 瘦身**：

```bash

```
