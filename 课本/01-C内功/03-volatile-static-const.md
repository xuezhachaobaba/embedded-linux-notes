# 03 三个关键字：`volatile` / `static` / `const`

> 这三个是 C 面试的常驻考点，嵌入式尤其爱考 `volatile`（它是嵌入式区别于纯软件的标志）。本节务必把"为什么"想透。

## 学习目标

- 理解 `volatile` 的作用、三大场景，以及它**不**保证什么
- 理解 `static` 的两种用法（局部持久化、全局/函数限文件）
- 理解 `const` 的只读语义和工程用法（指针 const 复习 02b）

## 本课知识点（作业每题标 `[考：X]`）

1. `volatile` 是什么：阻止编译器优化，强制每次读写内存
2. `volatile` 的三大使用场景：硬件寄存器 / 中断共享变量 / 多线程
3. `volatile` 的经典坑（`while(flag)` 被优化成死循环）
4. **`volatile` 不保证原子性、不保证线程安全**（面试最爱挖的坑）
5. `const volatile` 组合：只读但会变（硬件状态寄存器）
6. `static` 局部变量：跨函数调用保持值，只初始化一次
7. `static` 全局变量 / 函数：限制在本文件内（文件私有）
8. `const`：只读变量 + const 参数（指针 const 见 02b 知识点7）

---

## 1. volatile 是什么　`[知识点1]`

`volatile` 告诉编译器：**这个变量的值随时可能被"当前代码流之外"的力量改变，别自作主张优化它，每次都老老实实从内存读写，别缓存到寄存器。**

```c
volatile int flag;
```

## 2. volatile 的三大使用场景　`[知识点2]`

**① 内存映射的硬件寄存器**——读写寄存器有副作用，访问不能被合并/删掉：
```c
volatile uint32_t *gpio = (volatile uint32_t*)0x40021000;
```

**② 中断（ISR）共享的变量**——主循环在等，中断随时改它：
```c
volatile int data_ready = 0;   // 中断里会置 1
```

**③ 多线程共享变量**——（注意：见知识点 4，volatile 在这里不够用）

## 3. volatile 的经典坑　`[知识点3]` ⭐面试高频

```c
int flag = 0;          // 会被中断设成 1
while (flag == 0) { }  // 等 flag 变 1
```
开了优化（`-O2`）时，编译器认为"`flag` 在循环里没人改"，于是**只读一次** `flag`、缓存起来 → 哪怕中断把 `flag` 改成 1，主循环也看不到 → **死循环**。

修法：`volatile int flag = 0;`，编译器每次都重新从内存读 `flag`。

> 想亲眼验证可以 `gcc -O2 -S` 看汇编：没 volatile 的版本 `flag` 只被读一次；volatile 的版本每次循环都重新 load。

## 4. volatile 不保证原子性、不保证线程安全　`[知识点4]` ⭐面试最爱挖的坑

两个常见误解，**都是错的**：

- ❌ "volatile 让读写变成原子操作" → **错**。`volatile` 只防优化，**不保证一次读/写不被打断**。`volatile int64_t` 在 32 位机上读写仍可能被打断。
- ❌ "volatile 能保证多线程安全" → **错**。它不保证**内存顺序**、不保证原子。多线程正确同步要靠**互斥锁 / 原子变量**。

> 记住：**C 的 volatile ≠ Java 的 volatile**。C 的 volatile 只管"别优化、老实访问内存"，仅此而已。

## 5. const volatile 组合　`[知识点5]`

看起来矛盾，实则很常见：**"代码里不能改它（const），但它会被硬件改（volatile）"**——典型的**只读状态寄存器**。

```c
const volatile uint32_t *status = (const volatile uint32_t*)0x40021010;
uint32_t s = *status;   // 每次都要重新读硬件，且代码不能写它
```

## 6. static 局部变量　`[知识点6]`

```c
int counter(void) {
    static int n = 0;   // 只在程序启动时初始化一次，之后跨调用保持值
    return ++n;
}
counter();  // 1
counter();  // 2
counter();  // 3
```
- 普通局部变量每次进函数都重新分配（在**栈**上）、重新初始化。
- `static` 局部变量存在**静态存储区**（`.data` 或 `.bss` 段），**只初始化一次**，函数返回后不销毁。

## 7. static 全局变量 / 函数　`[知识点7]`

`static` 放在全局变量或函数前 = **"只在本 .c 文件内可见"**（内部链接，文件私有）。

```c
// a.c
static int secret = 42;        // 别的 .c 文件用 extern 也访问不到
static void helper(void) {}    // 只能被 a.c 内的函数调用
```
- 不加 `static` 的全局变量/函数是**外部链接**，别的文件 `extern` 一下就能用。
- 工程意义：把"内部辅助"藏起来，避免命名冲突、限制作用域。

## 8. const：只读　`[知识点8]`

```c
const int x = 5;
x = 10;            // ❌ 编译错误，const 变量不可改
```
- **const 变量**：初始化后不可改（自文档化 + 防误改 + 利于优化）。
- **const 函数参数**：`void print(const char *s)` —— 向调用者承诺"我不改你的数据"，编译器也会帮你检查。
- **const 指针**（三种）：见 02b 知识点 7，口诀"const 在 `*` 左边指的东西只读，右边指针本身只读"。

> 嵌入式小知识：全局 `const` 变量有时会被链接器放进 **Flash/ROM**（只读存储器），省宝贵的 RAM——这也是 const 在嵌入式里的实际价值之一。
