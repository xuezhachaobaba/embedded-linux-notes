## 第一个程序

在 WSL2 里选个目录（比如这个项目目录），新建 `hello.c`：

```c
#include <stdio.h>

int main(void) {
    printf("Hello, Embedded Linux!\n");
    return 0;
}
```

编译并运行：

```bash
gcc hello.c -o hello    # 编译：把 hello.c 编成可执行文件 hello
./hello                  # 运行
```

看到 `Hello, Embedded Linux!` 就成功了。🎉

## gcc 编译的四个阶段（理解即可，面试也会问）

`gcc hello.c -o hello` 一条命令其实偷偷干了四步：

1. **预处理**（`-E`）：展开 `#include`、`#define` → 生成纯 C 代码
2. **编译**（`-S`）：C 代码 → 汇编代码（`.s`）
3. **汇编**（`-c`）：汇编代码 → 机器码（`.o` 目标文件）
4. **链接**（默认）：把目标文件和库拼成最终可执行文件

记住顺序口诀：**预 → 编 → 汇 → 链**。

## 几个常用编译选项（养成好习惯）

```bash
gcc -Wall -g hello.c -o hello
```

| 选项 | 作用 | 为什么要用 |
|---|---|---|
| `-Wall` | 打开常用警告 | **必加**。警告里常藏着 bug |
| `-g` | 保留调试信息 | 以后用 gdb 调试时必须 |
| `-O2` | 优化（O0/O1/O2/O3）| 调试时别开，发布时再开 |
| `-std=c11` | 指定 C 标准 | 现代写法建议 `c11` 或 `c17` |

> 建议默认就用：`gcc -Wall -g -std=c11 hello.c -o hello`

**3.（理解）** gcc 编译的四个阶段按顺序是哪四个？

<details><summary>👀 点开看答案</summary>

预处理 → 编译 → 汇编 → 链接（口诀：预编汇链）。

- 预处理：展开 `#include`、`#define`
- 编译：C → 汇编
- 汇编：汇编 → 机器码（`.o`）
- 链接：拼库，生成可执行文件

</details>

**4.（进阶）** 试着分步编译，亲眼看到中间产物：
```bash
gcc -E hello.c -o hello.i    # 只预处理
gcc -S hello.i -o hello.s    # 只编译，得到汇编
gcc -c hello.s -o hello.o    # 只汇编，得到目标文件
gcc hello.o -o hello         # 只链接
./hello
```
> 这一步能让你彻底理解"预编汇链"到底各产生了什么。
