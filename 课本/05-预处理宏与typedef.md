## 知识点 1：预处理器是什么

gcc 四阶段：**预 → 编 → 汇 → 链**（00 课口诀）。预处理器干活的阶段就是第一阶段，产出 `.i` 文件。

**本质：一个"文本替换机器"**——不懂 C 语法、不管类型、不做计算，只做字符串级别的查找替换和文件拷贝。你写的一切 `#` 开头的东西都归它管。

**眼见为实（跑这个）**：

```c
// dump.c
#include <stdio.h>
#define MAX 100

int main(void) {
    int a = MAX;
    return 0;
}
```

```bash
gcc -E dump.c -o dump.i    # 只跑到预处理就停
wc -l dump.i               # 几万行！stdio.h 整个被拷了进来
grep -n 'int a' dump.i     # 看到那行变成了 int a = 100;
```

预处理器做了两件事：把 `stdio.h` 内容原地展开（约 2 万行），把 `MAX` 替换成 `100`。**它不知道 100 是什么，纯替换**。

> 这就是为什么宏的坑都来自"它不懂语义"——知识点 3/4 全是这个根源。

## 知识点 2：无参宏（常量）vs const

```c
#define PI 3.14159        // 宏：编译前文本替换，没有类型、不占内存、没有作用域
const double pi = 3.14159; // const：编译期实体，有类型 double、有作用域、调试可见
```

| | `#define PI` | `const double pi` |
|---|---|---|
| 生效时机 | 预处理（编译前替换） | 编译期 |
| 有类型吗 | **没有**（就是文本） | 有（double） |
| 调试能看到吗 | 不能（名字消失了） | 能 |
| 作用域 | 从定义处到文件尾（不受 `{}` 限制！） | 遵守正常作用域 |

**坑**：宏没有作用域——在头文件里 `#define MAX 100`，所有包含它的 `.c` 里的 `MAX` 全遭殃，连别的想叫 MAX 的变量/函数名都会被替换掉。这是"能用 const 就用 const"的理由。

**但嵌入式里 `#define` 仍是主流**（寄存器地址、位掩码定义），因为：不占内存、能用在 `case` 标签/数组大小等**要求编译期常量**的地方（C89 时代的 const 不能当数组大小，C99 起可以了，但老代码全是宏）。

## 知识点 3：带参宏——两条括号铁律（笔试最爱）

```c
#define SQUARE(x)  x * x          // ❌ 错误写法
#define SQUARE(x)  ((x) * (x))    // ✅ 正确写法
```

**铁律 1：每个参数都要加括号**。调用 `SQUARE(a+b)`：

```
错误版展开：a + b * a + b     → a + (b*a) + b   优先级炸了
正确版展开：(a + b) * (a + b) ✅
```

**铁律 2：整个表达式也要加括号**。假设 `#define ADD(a,b) (a) + (b)`（只守了铁律1）：

```c
10 * ADD(2, 3)   // 展开成 10 * (2) + (3) = 23，不是 50！
```

守两条铁律的完整版：`#define ADD(a,b) ((a) + (b))` → `10 * ((2) + (3))` = 50 ✅

**面试标准话术**："带参宏的参数和整个表达式都要加括号，因为宏是文本替换，不知道调用处的优先级环境。"

### 带参宏 vs 函数

| | 宏 | 函数 |
|---|---|---|
| 何时处理 | 预处理（原地展开） | 运行时调用 |
| 开销 | 无调用开销（内联展开）⭐ 嵌入式爱用 | 压栈/跳转/出栈 |
| 类型检查 | **没有**（哑巴替换） | 有（编译器把关） |
| 调试 | 难（展开后没有宏了） | 容易 |
| 参数求值次数 | **可能多次**！（见知识点4） | 恰好一次 |

## 知识点 4：宏的副作用——`MAX(i++, j)` 翻车现场（经典）

```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))

int i = 5, j = 3;
int m = MAX(i++, j);
printf("%d %d %d\n", m, i, j);   // 预测一下？
```

展开后：

```c
int m = ((i++) > (j) ? (i++) : (j));
```

`i++` 出现了**两次**！执行过程：先比较 `i++ > j`（用 5 比，i 变 6），条件真 → 再算 `i++`（用 6，i 变 7）→ m = 6。

**输出：`6 7 3`**——i 被加了两次，m 拿到的还不是原来的 5。

这就是表格里"参数求值多次"的具体样子。**规则：传给宏的参数里别带 `++`/`--`/函数调用等副作用**。函数没这问题（参数只求值一次）。

> 这题是笔试钉子户，变体极多（`SQUARE(i++)` 同理翻车）。看到宏 + `++` = 条件反射起疑心。

## 知识点 5：条件编译——头文件卫士（每个头文件都用）

```c
// myheader.h
#ifndef MYHEADER_H        // 如果没定义过 MYHEADER_H
#define MYHEADER_H        // 就定义它，然后 include guard 生效

// ... 真正的内容 ...

#endif                    // 第二次 include 时，MYHEADER_H 已存在 → 整段跳过
```

**为什么必须**：`#include` 是"把文件内容原地拷贝"。如果 a.h 被包含两次（比如 a.c 包含了 x.h 和 y.h，它俩又都包含 a.h），结构体/函数声明会出现两份 → **重复定义编译错误**。卫士让第二次拷贝变成空。

**_IRQ 驱动场景**（以后天天见）：条件编译还用来切换平台/开关功能：

```c
#ifdef DEBUG
    printf("x = %d\n", x);      // 只有定义了 DEBUG 才编译这行
#endif

#if defined(BOARD_A)
    /* 板 A 的寄存器地址 */
#elif defined(BOARD_B)
    /* 板 B 的 */
#endif
```

编译时 `-DDEBUG` 就开、不传就关——**同一份代码裁出不同版本**，这是内核/驱动编译体系的地基。

常用家族：`#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` / `#if 0`（注释大段代码的惯用招）。

## 知识点 6：其他预处理杂项（知道即可）

```c
#undef MAX                  // 取消宏定义，后面的 MAX 不再替换

__FILE__                    // 当前文件名（字符串）
__LINE__                    // 当前行号（整数）
__DATE__ / __TIME__         // 编译日期/时间
__func__                    // 当前函数名（C99，严格说是编译器而非预处理器提供）
```

调试宏的经典用法：

```c
#define LOG(fmt, ...)  printf("[%s:%d] " fmt, __FILE__, __LINE__, ##__VA_ARGS__)
// LOG("x=%d\n", x) → [main.c:12] x=42
```

`#` 把参数变成字符串（`#x` → `"x"`），`##` 拼接标识符（`a##b` → `ab`）——见过能认出即可，阶段 3 看内核代码会遇到。

## 知识点 7：typedef vs #define（对比题）

```c
typedef unsigned int uint_t;      // 类型别名：编译器认识的新类型名
#define uint_t unsigned int       // 文本替换：预处理器傻替换
```

**大部分场景效果一样，两个地方分胜负：**

**① 指针类型——typedef 对、#define 错**：

```c
typedef int* int_ptr_t;
#define INT_PTR  int*

int_ptr_t p1, p2;    // p1、p2 都是 int*     ✅
INT_PTR   p3, p4;    // 展开成 int *p3, p4 → p3 是指针，p4 是 int！ ❌
```

**② 数组/函数指针类型——#define 根本写不出来**：

```c
typedef int (*handler_t)(int);          // "指向函数的指针"类型
handler_t h = my_func;                  // 不用 typedef 要写 int (*h)(int) = my_func;
```

驱动里满地都是 `typedef struct {...} xxx_t;`——省去到处写 `struct` 的同时给结构体起短名。

**结论**：起类型别名**一律用 typedef**（它真懂类型）；#define 留给常量和条件编译。
