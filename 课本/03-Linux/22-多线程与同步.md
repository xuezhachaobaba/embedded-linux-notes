## 知识点 1：线程 vs 进程——一张表说清谁共享谁

| | fork 出的进程 | pthread 出的线程 |
|---|---|---|
| 地址空间（全局/堆） | **各一份**（COW） | **共享同一份** |
| 打开的 fd | 共享（同一个 fd 表） | 共享 |
| 栈 | 各一份 | **各有自己的**（默认 8MB） |
| 寄存器 / PC | 各一份 | 各一份（不然没法各跑各的） |
| 创建/切换开销 | 重（复印房子） | 轻（多个人进同一间房） |
| 一个崩了 | 别人没事（隔离好） | **全体连坐**（一个线程段错误，整个进程死） |

- 内核视角：Linux 下**都是 task_struct**，线程 = 共享地址空间的"轻量进程"（clone 出来的兄弟）。21 课 task_struct 的知识直接复用。
- 传家一句话：**进程是资源分配的单位，线程是调度的单位**。

## 知识点 2：pthread 基操——create / join / void*

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

void* work(void* arg) {                       /* 线程函数：收 void* 返回 void* */
    const char* name = (const char*)arg;      /* 万能指针，进来先转型 */
    printf("[%s 线程] 我出生了\n", name);
    sleep(1);
    printf("[%s 线程] 干完了\n", name);
    return NULL;                              /* 也可以 return (void*)值 带东西回去 */
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, work, (void*)"A");   /* 参数4 = 传给 work 的 arg */
    pthread_create(&t2, NULL, work, (void*)"B");
    printf("[main] 两个线程已派出，我等它们\n");
    pthread_join(t1, NULL);                   /* 等它结束（类似 wait 收尸） */
    pthread_join(t2, NULL);
    printf("[main] 都回来了，收工\n");
    return 0;
}
```

实测（**跑两次顺序不一样**——线程谁先上 CPU 由调度器说了算）：

```
[A 线程] 我出生了
[main] 两个线程已派出，我等它们
[B 线程] 我出生了
[B 线程] 干完了
[A 线程] 干完了
[main] 都回来了，收工
```

- `pthread_create(&tid, NULL, 函数, arg)`：生出线程，立刻并发开跑。
- `pthread_join(tid, &ret)`：等指定线程结束，`void* ret` 能接住它 return 的东西——21 课 wait 的线程版。**不 join 也不 detach = 资源滞留**（僵尸线程的近亲）；不想等就 `pthread_detach(tid)` 说"完了自己走"。
- 线程想报身份：`pthread_self()`；main 自己也是线程。
- 各自的栈实测：两个线程各改各的局部变量，互不干扰，join 还能带回返回值——**全局共享、局部隔离**。

## 知识点 3：竞争条件——count++ 不是一步 ⭐ 本课核心

```c
#include <pthread.h>
#include <stdio.h>

long counter = 0;                     /* 全局：两个线程共享 */

void* add_a_million(void* arg) {
    for (long i = 0; i < 1000000; i++)
        counter++;                    /* 三步：读 → 加 → 写回 */
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, add_a_million, NULL);
    pthread_create(&t2, NULL, add_a_million, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("期望 2000000，实际 %ld，丢了 %ld 次\n", counter, 2000000 - counter);
    return 0;
}
```

`gcc -Wall -O0 -std=c11` 编译（**本实验必须 -O0**，原因见知识点 4），跑三次：

```
期望 2000000，实际 1124682，丢了 875318 次
期望 2000000，实际 1009463，丢了 990537 次
期望 2000000，实际 1113748，丢了 886252 次
```

**丢了将近一半，而且每次不一样。** 事故机制：`counter++` 在机器层面是**三步**——①把 counter 从内存读进寄存器 ②寄存器加 1 ③写回内存。A 线程刚做完①②，B 线程抢进来把①②③全做了一遍（counter: 5→6），A 回来接着做③，**把它手里的 6 写回去**——B 那次加就凭空消失了。两个线程只要在"读和写之间"被切开，就丢一次。

- 名词：**竞争条件（race condition）**——结果取决于谁先谁后，而谁先谁后不定。
- 铁律：**只要有多线程 + 至少一个在写同一变量，没锁就是错的**——哪怕"跑起来好像没事"。

## 知识点 4：-O2 把竞争藏起来——编译器也会骗你 ⭐

上面那个程序，换 `-O2` 编译再跑：

```
期望 2000000，实际 2000000，丢了 0 次
```

**居然对了？！** 不是修好了，是**藏起来了**：-O2 优化发现循环里 counter 没人"告诉"它会变，干脆把 counter 缓存在寄存器里，整个循环在寄存器里加完，最后一次性写回——每个线程各揣一份寄存器值，互相"错开"了，反而看不到丢失。竞争还在，只是这份数据没撞上。

- 这正是 03 课 volatile 的地盘：**编译器有权把内存值缓存进寄存器**（甚至删除它认为无用的读写）。
- 三条推论，面试都用得上：
  1. "跑对了"证明不了并发正确——数据、优化等级、时机一变就现形；
  2. 换 -O2 行为突变 = 优化的嫌疑犯之一（和 `= {0}` 进 .bss 一个套路：**预期和实测不符时别放过**）；
  3. volatile 只保证"每次老实读写内存"（治缓存），**不保证三步不被打断**（不治原子）——见知识点 8。

## 知识点 5：互斥锁——同一时刻只放一个进临界区

```c
#include <pthread.h>
#include <stdio.h>

long counter = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;   /* 静态初始化，最省事 */

void* add_a_million(void* arg) {
    for (long i = 0; i < 1000000; i++) {
        pthread_mutex_lock(&lock);      /* 进临界区：一次只放一个 */
        counter++;
        pthread_mutex_unlock(&lock);    /* 出临界区 */
    }
    return NULL;
}
/* main 同知识点 3 */
```

实测：`期望 2000000，实际 2000000`，跑多少次都是。

- mutex = 门上挂锁：lock 到 unlock 之间的**临界区**一次只进一个线程，counter++ 的三步从此**原子的发生**。
- **临界区越小越好**：锁是排队，锁的地盘越大，并发越白给。锁整个循环也能对，但两个线程就变成纯串行（作业里让你亲手对比）。
- 术语：lock 拿不到锁的线程**阻塞睡眠**（不烧 CPU，跟自旋锁的区别，内核课展开）。

## 知识点 6：忘了解锁 / 死锁——亲手卡死一次

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

void* work(void* arg) {
    pthread_mutex_lock((pthread_mutex_t*)arg);
    printf("线程：拿到锁，干完活，忘了解锁……\n");
    return NULL;                        /* 忘了 unlock */
}

int main(void) {
    pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
    pthread_t t;
    pthread_create(&t, NULL, work, &m);
    sleep(1);
    printf("main：我也想要锁（马上要永远卡住）\n");
    pthread_mutex_lock(&m);
    printf("main：拿到锁（这行永远打不出来）\n");
    return 0;
}
```

实测：输出两行后**程序一动不动**，`Ctrl+C` 才能杀掉。这就是"卡死"的体感。

- 忘 unlock = 别人永远进不来。C++ 视角老朋友：**这正该 RAII 来治**（lock 在构造、unlock 在析构——标准库的 `std::lock_guard` 就是这个，你 C05 已经会思想了）。
- 经典**死锁**（两个锁、顺序相反）：A 拿锁1 等锁2，B 拿锁2 等锁1，互相等到天荒地老。预防口诀：**所有线程按同样的顺序拿锁**。
- 自查手段：程序失联时 `gdb -p PID` 或 `cat /proc/PID/stack`/`task` 类工具看它卡在哪个调用上——先记名词，调试课细讲。

## 知识点 7：条件变量——"等通知"的正确姿势

mutex 管"一次进一个"，条件变量管"**没轮到就睡觉，轮到了叫我**"（忙等 sleep 轮询的反面）。最小模型：一个厨师一个食客：

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t  dish_ready = PTHREAD_COND_INITIALIZER;
int dish = 0;                           /* 0=盘子空，1=有菜 */

void* cook(void* arg) {
    for (int i = 1; i <= 3; i++) {
        sleep(1);
        pthread_mutex_lock(&m);
        dish = i;
        printf("厨师：第 %d 道菜上桌，敲铃\n", i);
        pthread_cond_signal(&dish_ready);     /* 敲铃：叫醒等的人 */
        pthread_mutex_unlock(&m);
    }
    return NULL;
}

void* eater(void* arg) {
    for (int i = 1; i <= 3; i++) {
        pthread_mutex_lock(&m);
        while (dish == 0)                    /* while 不是 if！ */
            pthread_cond_wait(&dish_ready, &m);  /* 原子地[放锁+睡觉]，醒来时锁已拿回 */
        printf("食客：吃到第 %d 道菜\n", dish);
        dish = 0;
        pthread_mutex_unlock(&m);
    }
    return NULL;
}

int main(void) {
    pthread_t c, e;
    pthread_create(&e, NULL, eater, NULL);
    pthread_create(&c, NULL, cook, NULL);
    pthread_join(e, NULL);
    pthread_join(c, NULL);
    printf("饭局结束\n");
    return 0;
}
```

实测输出严格交替：厨师上菜 → 食客吃 → 三轮 → 饭局结束。

- `pthread_cond_wait(&cond, &m)` 一行干三件事：**放下锁 + 睡觉 + 被叫醒后拿回锁**（前两步原子）。醒来从 wait 的下一行继续。
- **while 而不是 if**：醒来后必须**重新检查条件**——可能被"虚假唤醒"（没人敲铃也醒了）或别人抢先吃掉了。这是条件变量的标准姿势，面试爱抠这一字之差。
- signal 叫醒**一个**，broadcast 叫醒**全部**。

## 知识点 8：选型口述 + volatile 的边界（面试高频）

**fork 还是线程？**
- 要**隔离/稳定**（一个崩了别人活着、权限边界）→ 进程：浏览器多标签、nginx worker。
- 要**共享数据、低开销**（同一份内存猛算、聊天服务器每连接一个流）→ 线程。
- 嵌入式常见答案：数据共享简单就线程+锁；任务独立、怕连环崩就进程。别背模板，说**取舍**。

**volatile 能代替锁吗？——不能。**（03 课三条不保证的实战版）
- volatile 治的是"**编译器**把内存值缓存进寄存器"（知识点 4 的 -O2 现象）；
- 锁治的是"**两个线程的三步读写被切开**"（知识点 3 的丢更新）。
- 病因不同，药不同；多线程正确性靠锁（或原子操作），volatile 只保证"读的是内存"。
