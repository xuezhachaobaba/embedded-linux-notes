## 知识点 1：系统调用 vs 标准库——两套接口，一个内核

你一直在用的 `fopen/fgets/fclose` 是**标准库**（C 语言的行李，任何平台都有）。本课的 `open/read/write/close` 是**系统调用**——直接敲内核的门：

```
你的程序 → fopen/fread（库函数，带缓冲、搬家包装）→ open/read（系统调用）→ 内核
```

- 库函数 = 系统调用的"精装修版"：自带缓冲区（攒够一锅再端给内核）、跨平台
- 系统调用 = 毛坯但直通：没有中间商，嵌入式/驱动/内核代码全用这套
- **为什么必须学**：阶段 3 写驱动时你要**实现** open/read/write 给别人调（file_operations！）；内核态没有 stdio，只有这一层
- 判断题常考：「fread 和 read 的区别？」——答"库函数 vs 系统调用 + 缓冲"，别答"功能差不多"

## 知识点 2：fd——进程的"遥控器编号"（0/1/2 的真身）

每个进程有一张**打开文件表**，fd（file descriptor，文件描述符）就是表的**下标**：

- `open()` 成功 → 内核给你一个**当前最小的空闲非负整数**
- **0 = 标准输入、1 = 标准输出、2 = 标准错误**——进程一出生内核就替你开好了这三个

所以 10 课的谜底揭晓：

```bash
gcc a.c > log.txt     # > 的意思是：把 1 号 fd 改接（重定向）到 log.txt
gcc a.c 2> err.txt    # 2> ：把 2 号 fd 接到 err.txt
cmd > all.txt 2>&1    # 2>&1：把 2 号接到 1 号当前指着的地方（合流）
```

**眼见为实**——`/proc/self/fd` 就是你自己的打开文件表（10 课"内核假文件"回接）：

```bash
ls -l /proc/self/fd
# 0 -> /dev/pts/0     ← 你的键盘（终端）
# 1 -> /dev/pts/0     ← 你的屏幕
# 2 -> /dev/pts/0     ← 报错也上屏
# 加了 > log.txt 再看：1 -> log.txt ！
```

fd 分配规则实测（本课作业 Q2）：

```c
int a = open(...);  // 3   ——0/1/2 被占了，从最小空闲的开始
int b = open(...);  // 4
int c = open(...);  // 5
close(b);
int d = open(...);  // 4   ——b 的坑空出来，d 补位！
```

## 知识点 3：open()——flags 组合 + 权限

```c
#include <fcntl.h>
int fd = open("data.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
```

- 返回：成功给 fd，**失败给 -1**（记住：不是 0！0 是 stdin）
- 前三个 flags **三选一**：`O_RDONLY` 只读 / `O_WRONLY` 只写 / `O_RDWR` 读写
- 按需叠加（`|` 组合，位运算的老本行）：`O_CREAT` 不存在就创建 / `O_TRUNC` 存在就清空 / `O_APPEND` 每次写都跳到末尾
- **权限 0644 只在带 O_CREAT 时才有意义**：8 进制，属主 rw-、组 r--、其他 r--（就是 `ls -l` 里的 `-rw-r--r--`）
- 坑：0644 是"许愿"，真正权限 = 0644 & ~umask（默认 umask 022 时正好 0644，别纠结，先记结果）

## 知识点 4：read()/write()——返回值三义 + 循环模板

```c
#include <unistd.h>
char buf[4096];
ssize_t n = read(fd, buf, sizeof(buf));
```

`n` 有**三种含义**，判断程序全靠它：

| n | 含义 |
|---|------|
| > 0 | 实际读到的字节数（**可能小于你要的**！键盘、网络、读到最后一段都会发生）|
| 0   | **读到文件尾（EOF）**——不是出错！ |
| -1  | 出错（errno 记录原因） |

**整个文件 I/O 的灵魂模板**（cp/more/网络收发全是它）：

```c
ssize_t n;
while ((n = read(src, buf, sizeof(buf))) > 0)
    write(dst, buf, n);        // 读多少写多少
```

write 同理返回"实际写出字节数"，严谨代码要检查它 == n（本课先信任它）。

## 知识点 5：close() 与 fd 泄漏

```c
close(fd);     // 还回编号，内核才能真正释放资源
```

- fd 是**有限资源**（上限可查：`ulimit -n`，你这台机是 1048576；很多嵌入式系统只有 1024）
- **open 了不 close = fd 泄漏**：进程的打开文件表一路涨，最终所有 open 报 `Too many open files`（作业 Q6 你会亲手把进程撑爆）
- 进程退出时内核会兜底回收所有 fd——但别指望它，长期运行的服务（嵌入式设备动辄跑几个月）全靠你自己 close
- 和堆内存一个哲学：**谁申请谁归还，不还就漏**——06 课的老朋友换了个资源类型

## 知识点 6：错误处理——errno 与 perror

```c
int fd = open("不存在的文件", O_RDONLY);
if (fd == -1) {
    perror("open 失败");     // 打印："open 失败: No such file or directory"
    return 1;
}
```

- 失败时内核把错误码放进全局变量 **errno**（`#include <errno.h>`）
- `perror("前缀")` = 打印"前缀： errno 对应的人话"——你 10 课见过的所有报错尾缀全是它打的
- **规矩：检查每个系统调用的返回值**。open 可能失败、read 可能被信号打断、磁盘可能满——嵌入式代码一句都不许裸奔

## 知识点 7：lseek 与 O_APPEND——读写位置

每个 fd 有一个**偏移量**（当前读写位置），read/write 都从它开始、做完自动后移。

```c
#include <unistd.h>
off_t size = lseek(fd, 0, SEEK_END);   // 跳到末尾，返回值 = 文件大小！
lseek(fd, 0, SEEK_SET);                // 跳回开头
```

- 不想手动管位置：打开时加 `O_APPEND`——每次 write 强制跳到末尾（多进程同时写日志不互相覆盖，就靠它）
- 实验预告（作业 Q7）：**不加 O_APPEND、也不 lseek**，两次 write 第二次会**从头覆盖**——位置在 open 时归零，write 只管"从当前位置往下写"

## 知识点 8：一切皆文件——嵌入式核心思想

Linux 把**一切资源都做成文件**，于是"操作资源"永远 = open/read/write/close 一套动作：

| 资源 | 文件样子 | 干什么 |
|------|----------|--------|
| 串口 | `/dev/ttyUSB0` | open 后 read/write 就是收发数据 |
| 屏幕/键盘 | `/dev/tty`、fd 0/1/2 | 10 课的重定向 |
| 进程信息 | `/proc/self/fd` | 作业 Q2 亲眼看自己的 fd 表 |
| 内核参数 | `/proc/sys/...` | 读 = 查询，写 = 改配置 |
| **你未来写的传感器** | `/dev/my_sensor` | 阶段 3：驱动实现 file_operations，应用层 open/read 就能用 |

这就是 C03 那句话的完整闭环：**file_operations 的 open/read/write 就是为这一层准备的接口**——应用程序 `open("/dev/xxx")` 时，内核回头调你驱动里注册的那个 open。现在你从"调用方"把这条路走一遍，阶段 3 你再站到"实现方"。

## 综合示例：mycp——一个最小的 cp 命令

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(int argc, char **argv) {
    if (argc != 3) {
        printf("用法: %s 源 目标\n", argv[0]);
        return 1;
    }
    int src = open(argv[1], O_RDONLY);
    if (src == -1) { perror("open 源"); return 1; }

    int dst = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst == -1) { perror("open 目标"); return 1; }

    char buf[4096];
    ssize_t n;
    while ((n = read(src, buf, sizeof(buf))) > 0)
        write(dst, buf, n);

    close(src);
    close(dst);
    return 0;
}
```

**先预测再跑**：`./mycp a.txt b.txt` 后 b 的权限是多少？`./mycp 不存在 x` 的退出码？复制一个二进制文件（比如 mycp 自己）再 diff，模板对二进制也成立吗？
