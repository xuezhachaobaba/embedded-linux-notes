## 知识点 1：进程与 PID——程序是文件，进程是活动

- **程序** = 硬盘上的可执行文件（死的）；**进程** = 正在运行的实例（活的）。一个程序可以起 N 个进程（开三个 `bash` 就是三份）。
- 内核给每个进程发身份证 **PID**（正整数，唯一）。内核内部用结构体 `task_struct` 记着一个进程的一切（PID、状态、打开的文件表、地址空间……）——C03 说"内核不认识类"，但内核自己就是最大的结构体用户。
- 常用侦查手段：

```bash
ps -o pid,ppid,stat,cmd        # 自己的：PID、父PID、状态、命令行
ps aux | grep a.out            # 全系统找人
echo $$                        # 当前 shell 自己的 PID
```

- `PPID` = 父进程号。**每个进程都是别人生出来的**（fork 出来的），所以有爹是常态——这条直接通向知识点 4。

## 知识点 2：fork——一次调用，两次返回 ⭐

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }   /* 失败：进程太多等 */
    if (pid == 0) {
        printf("[子] pid=%d ppid=%d fork返回=%d\n", getpid(), getppid(), pid);
    } else {
        printf("[父] pid=%d 子pid=%d fork返回=%d\n", getpid(), pid, pid);
    }
    return 0;
}
```

实测（跑两次，父子谁先打印**不保证**，每次可能不同）：

```
[父] pid=367717 子pid=367718 fork返回=367718
[子] pid=367718 ppid=367717 fork返回=0
```

- fork 干的事：**把当前进程整个复印一份**，从 fork 这一行开始兵分两路各跑各的。
- **一次调用、两次返回**——这句话是面试标准答案，展开说：
  - 父进程那边：返回**新孩子的 PID**（>0）
  - 子进程那边：返回 **0**
  - 出错：-1（此时没有孩子）
- 所以模板永远是 `if (pid == 0) { 子进程代码 } else { 父进程代码 }`——拿返回值分道。
- 复印得有多彻底？**地址空间、打开的 fd、变量值……全拷**。但两个进程地址空间独立，之后各改各的互不影响（见知识点 3 的 COW）。

## 知识点 3：写时复制 COW + 缓冲区复制事故

**COW（Copy-On-Write）**：fork 时内核**并不真复制内存**，只把两边的页都标成"只读、共享"；谁先写，谁触发缺页异常，内核这才给谁复制那一页。理由：fork 之后往往紧跟 exec（知识点 6），拷了也白拷。面试一句话：**"fork 不立即复制内存，谁写谁才复制，省时间省空间。"**

但"全拷"有一个立刻能看见的鬼——**stdio 用户态缓冲区也在被拷之列**：

```c
#include <stdio.h>
#include <unistd.h>
int main(void) {
    printf("A");          /* 没有 \n，还躺在用户态缓冲区里 */
    fork();
    printf("B\n");
    return 0;
}
```

实测（终端、管道下都一样）：

```
AB
AB
```

**A 打了两遍！** 解释：`printf("A")` 没遇到 `\n` 又没冲缓冲，"A" 还在用户态缓冲区；fork 把**缓冲区连同内容**一起复印给了孩子；父子各自 `printf("B\n")` 时连着库存的 A 一起冲出去。**换 `write(1, "A", 1)`（内核态直发，无用户态缓冲）就只打一遍**——这正是 20 课 syscalls vs stdio 那一节埋的伏笔。

- 坑位总结：**fork 前的输出必须亲手冲干净**（`fflush(stdout)` 或带 `\n`），否则复印一份。
- minishell 的提示符 `printf("mini> ")` 不带 `\n`，后面必须跟 `fflush(stdout)`，就是同一个坑的正面用法。

## 知识点 4：僵尸与孤儿——爹儿关系的两种死法 ⭐

**僵尸（zombie）**：子进程死了，父进程**不收尸**（不 wait），内核必须留着那具尸体（PID + 退出状态 + task_struct 最小骨架）等爹来问。状态标记 `Z`，`ps` 里显示 `<defunct>`：

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
int main(void) {
    pid_t pid = fork();
    if (pid == 0) { printf("子进程 %d 马上退出\n", getpid()); return 42; }
    printf("父进程 %d 睡 10 秒，期间子进程是僵尸\n", getpid());
    sleep(10);            /* 故意不 wait */
    return 0;
}
```

另开一个终端，10 秒内：

```bash
$ ps -o pid,ppid,stat,cmd -C 03_zombie
    PID    PPID STAT CMD
 367742  367735 S    ./03_zombie          ← 爹，还在睡
 367743  367742 Z    [03_zombie] <defunct> ← 尸体！
```

**孤儿（orphan）**：反过来，**爹先死**。孩子还活着，PID 表里不能没有爹，内核把它过继给 1 号进程（systemd/init）：

```c
if (pid == 0) {
    printf("子进程：生父=%d\n", getppid());
    sleep(2);                          /* 等生父先死 */
    printf("子进程：现在的养父=%d\n", getppid());
    return 0;
}
return 0;                               /* 爹立刻退出 → 孩子成孤儿 */
```

实测：

```
子进程：生父=368056
子进程：现在的养父=1        ← systemd 收养，不会没人管
```

- 面试对答：**僵尸 = 儿死爹不收（爹的锅，wait 就消）；孤儿 = 爹死儿还在（不是病，systemd 领养）**。僵尸积累多了会耗尽 PID，才是真事故。
- 解药预告：爹 `wait()`（知识点 5）；爹想不阻塞地收，`waitpid(WNOHANG)`；爹压根不想管，注册 `SIGCHLD` 处理或 `signal(SIGCHLD, SIG_IGN)`——信号是 22/23 课的事，先记名词。

## 知识点 5：wait / waitpid——收尸、验尸

```c
#include <stdio.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int main(void) {
    pid_t pid = fork();
    if (pid == 0) { printf("子进程干活 1 秒...\n"); sleep(1); return 42; }
    int status = 0;
    pid_t w = wait(&status);           /* 阻塞，直到有一个孩子死 */
    printf("父进程：回收了 %d，正常退出=%d，退出码=%d\n",
           w, WIFEXITED(status), WEXITSTATUS(status));
    return 0;
}
```

实测：

```
子进程干活 1 秒...
父进程：回收了 367752，正常退出=1，退出码=42
```

- `wait(&status)`：**阻塞**等任意一个孩子退出，收尸并填 status。返回值 = 收到的孩子 PID。
- status 是个位打包的整数，**不能直接用**，拆包用宏：
  - `WIFEXITED(status)`：是不是正常退出（return / exit）
  - `WEXITSTATUS(status)`：退出码（仅当 WIFEXITED 为真才有意义）
  - 被信号打死时用 `WIFSIGNALED` / `WTERMSIG`（22 课信号见）
- `waitpid(pid, &status, 选项)`：指定收哪个孩子；`WNOHANG` = 没死就立刻返回 0（非阻塞轮询），长跑程序不想被孩子卡住时用。
- 没孩子可收时 wait 返回 -1——循环收尸收干净的标准判据。

## 知识点 6：exec 族——换马甲，不换 PID

```c
#include <stdio.h>
#include <unistd.h>
int main(void) {
    printf("换马甲前 pid=%d\n", getpid());
    execlp("ls", "ls", "-l", "/tmp", (char*)NULL);
    perror("execlp");      /* 只有失败才走得到这里 */
    return 1;
}
```

实测输出：先打一行"换马甲前"，然后直接是 **ls 的结果**——"换马甲后"三个字永远打不出来，因为 execlp 一成功，**当前进程的程序被整个替换成 ls**：旧代码、旧堆栈全部作废，从 ls 的 main 重新开始，**但 PID 没变**（还是同一个"人"，换了套剧本）。

- **成功时不返回**（旧代码都没了，返回给谁？）；**失败返回 -1**。所以 perror 那两行是"失败保险丝"，写上就对了：

```c
execlp("no-such-cmd", "no-such-cmd", (char*)NULL);
perror("execlp 失败");        → execlp 失败: No such file or directory，退出码 127
```

- 名字规律（面试爱问）：
  - **l** = list：参数一个一个列，**以 `(char*)NULL` 收尾**（忘了 NULL = 越界读，段错误常客）
  - **v** = vector：参数打包成 `char *argv[]` 数组传
  - **p** = path：去 PATH 里找命令（`ls` 就行）；**不带 p** 要给全路径（`/bin/ls`）
  - 组合出 `execl / execlp / execv / execvp`，加 e 还有自带环境变量版
- 127 = shell 约定的"命令没找到"退出码（下个知识点验证）。

## 知识点 7：退出码与 `echo $?`——进程的遗言

- 进程的遗言 = 退出码，shell 用 `echo $?` 收：

```bash
$ ./08_code; echo "shell 眼中 $? = $?"
WEXITSTATUS(256) = 0
shell 眼中 $? = 44
```

上面这个程序 `return 300`，shell 却看到 **44**；子进程 `return 256`，爹收尸收到 **0**。原因：**退出码只保留低 8 位**（0~255）。300 = 0x12C → 低 8 位 0x2C = 44；256 = 0x100 → 低 8 位 = 0。塞大数进去等于自我截断。
- 约定速记：**0 = 成功；非 0 = 失败原因**；1 通用错误；**127 = 命令不存在**（知识点 6 实测过）；126 = 有但没权限执行。
- `return n` 和 `exit(n)` 在 main 里等价；`_exit()` 不走 stdio 冲缓冲（少用）。C 课讲过 return 给谁——现在闭环了：**给 wait 你的人**。

## 知识点 8：组合拳——shell 的本质 ⭐

bash 敲 `ls -l` 回车的那一瞬，内核里发生的三板斧：

1. **bash fork** 出一个分身
2. 分身 **execvp("ls", ...)** 换成 ls 开干（bash 本体毫发无损，还能继续收命令）
3. bash **wait** 收尸、拿退出码存进 `$?`

这套写成代码就是迷你 shell（综合示例）。为什么 fork + exec 两步而不是一步"创个新进程"？——**fork 和 exec 之间可以插手脚**：重定向就是在那个窗口里 `dup2` 改 fd（23 课 IPC + 20 课 fd 复用汇合处）。

## 综合示例：mini shell（一页串起本课）

```c
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    char line[256];
    while (1) {
        printf("mini> ");
        fflush(stdout);                      /* 无 \n，手动冲缓冲（知识点3 的坑） */
        if (!fgets(line, sizeof(line), stdin)) break;
        line[strcspn(line, "\n")] = '\0';    /* 剥掉换行符 */
        if (line[0] == '\0') continue;

        char *argv[64] = {0};
        int argc = 0;
        char *tok = strtok(line, " ");       /* 10 课 strtok 回接 */
        while (tok && argc < 63) {
            argv[argc++] = tok;
            tok = strtok(NULL, " ");
        }
        if (strcmp(argv[0], "quit") == 0) break;

        pid_t pid = fork();
        if (pid == 0) {
            execvp(argv[0], argv);           /* 子进程换马甲去干活 */
            perror(argv[0]);                 /* 走到这 = 命令不存在 */
            return 127;
        }
        int st;
        wait(&st);                           /* 父进程等它收尸 */
    }
    return 0;
}
```

实测：

```
mini> echo hello mini
hello mini
mini> ls 06_shell.c
06_shell.c
mini> badcmd
badcmd: No such file or directory
mini> pwd
/tmp/L21
mini> quit
```

逐行对应：fgets 读命令（10 课）、strtok 切词、fork 分身、execvp 换马甲、perror+127 是失败保险丝、wait 收尸。**这就是一个能用的 shell 骨架**——每行都在本课知识点里。
