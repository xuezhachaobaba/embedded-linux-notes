## 知识点 1：结构体 sizeof——对齐规则三条（必背）

先看事实，再讲规则。**跑这个**：

```c
#include <stdio.h>
#include <stdint.h>

struct A {
    char  c;    // 1 字节
    int   i;    // 4 字节
    char  d;    // 1 字节
};

struct B {
    int   i;
    char  c;
    char  d;
};

int main(void) {
    printf("sizeof(struct A) = %zu\n", sizeof(struct A));
    printf("sizeof(struct B) = %zu\n", sizeof(struct B));
    return 0;
}
```

**先预测再跑**。如果你预测 6 和 6（1+4+1），跑出来会是 **12 和 8**——差出来的就是"对齐"。

### 三条规则（背下来）

1. **每个成员的偏移量**（相对结构体开头）必须是 `min(成员大小, 对齐系数)` 的整数倍——不够就在前面**填 padding**。
   - 对齐系数默认就是成员自己的大小（int → 4 的倍数偏移，char → 1，double → 8）。
2. **结构体总大小**必须是**最大成员对齐值**的整数倍——不够就在**末尾**补 padding。
3. 嵌套结构体：内层结构体的对齐值 = 它自己的最大成员对齐值。

### 用规则算一遍 struct A（char, int, char）

```
偏移   内容
0      c (char, 1字节)
1-3    padding 3字节     ← 规则1：i 需要 4 的倍数偏移，1 不是，补到 4
4-7    i (int, 4字节)
8      d (char, 1字节)
9-11   padding 3字节     ← 规则2：总大小需是 4（最大成员 int）的倍数，9→12
```

→ **12 字节**。struct B（int, char, char）：4 + 1 + 1 = 6，补到 8 的倍数？不对——**最大成员是 int（4）**，补到 4 的倍数 → **8 字节**。

### 面试标准答法

> "每个成员的偏移要对齐到自身大小的整数倍，结构体总大小要对齐到最大成员大小的整数倍，不足处编译器插 padding。"

### 坑

- **成员顺序影响大小**：同样三个成员，A 排法 12 字节、B 排法 8 字节。写结构体时**大成员放前面**是个免费优化。
- 数组作为成员：`int a[10]` 对齐值看**元素**（4），不是整个数组的 40。
- `sizeof(空结构体)` 在 C 里是不完整类型会报错；C++ 里是 1（保证不同对象不同地址）——知道即可。

## 知识点 2：为什么需要对齐（答 why）

CPU 不是按单字节读内存的，是**按字（word）成块读**的。x86-64 一次读 8 字节、且地址必须是 8 的倍数。

拿 `struct A` 里那个 int 举例：如果 int 不放在 4 的倍数地址上，它就可能**横跨两个 8 字节块**——CPU 得读两次、拼接，才能得到一个完整的 int（慢）。放在 4 的倍数地址上，一次就读到。

所以对齐 = **用空间换时间**。struct A 用 12 字节存 6 字节的数据，多花 6 字节，换来每次访问都一步到位。

> 深挖一句（面试加分）：x86 其实**允许**非对齐访问（只是慢）；但很多 ARM/内核场景非对齐访问会**直接异常**。所以内核和硬件结构体对对齐极其敏感——这是驱动工程师的基本功。

## 知识点 3：压缩——`#pragma pack` / `__attribute__((packed))`

有时空间比速度贵：网络协议头、硬件寄存器映射、文件格式。这时要**取消 padding**：

```c
#pragma pack(push, 1)          // 按 1 字节对齐（= 不对齐）
struct P {
    char  c;
    int   i;
    char  d;
};
#pragma pack(pop)
// sizeof(struct P) = 6   ← 1+4+1，没有 padding
```

gcc 写法（效果一样，驱动里更常见）：

```c
struct __attribute__((packed)) P {
    char c;
    int  i;
    char d;
};
```

### 坑（面试爱问 packed 的代价）

- **代价 1：慢**——成员可能非对齐，x86 上变慢，某些 ARM 上直接崩（内核里 packed 结构体取成员地址是危险动作）。
- **代价 2：**`packed` 结构体的成员指针不能随便解引用（可能非对齐）——安全做法是 `memcpy` 整个结构体或成员出来再用。
- 用途记牢：**协议解析、寄存器映射**（这两处"内存布局必须和数据格式严丝合缝"）。

## 知识点 4：大小端（Big/Little Endian）——必考

一个多字节整数（比如 4 字节的 0x12345678）在内存里怎么摆？两种流派：

```
地址：      0x00   0x01   0x02   0x03
小端：      78     56     34     12    ← 低位字节放低地址（"低低"）
大端：      12     34     56     78    ← 高位字节放低地址
```

**记忆口诀**：
- **小端**：低字节在低地址（x86、你的 WSL、绝大多数 ARM 默认）
- **大端**：高字节在低地址（网络字节序、部分老 PowerPC/MIPS）
- 最快记法：小端 = "倒着存"（0x12345678 存成 78 56 34 12）。

### 为什么会两种都存在（面试常问）

历史原因：Intel 早期选小端（低位先走，符合电路演算习惯），网络协议鼻祖 IBM/Motorola 选大端（人读数字的顺序）。都合理，都有海量遗产，改不了了。

### 快速判断口诀表

| 场景 | 字节序 |
|------|--------|
| x86 / x86-64（你的电脑） | 小端 |
| ARM（默认、跑 Linux 的 RK3568 等） | 小端 |
| ARM（可配，某些裸机配置） | 大端 |
| **网络字节序** | **大端** |
| PowerPC 老机型、SPARC | 大端 |

## 知识点 4b：什么时候真的在意大小端

日常写 x86 程序几乎不用在意（自己机器内部一致）。**必须处理的两种场合**：

1. **网络通信**：TCP/IP 规定网上传的字节序是**大端**（叫"网络字节序"）。发多字节整数前要转（`htons/htonl`），收到要转回来（`ntohs/ntohl`）。h=host, n=network, s=short(16位), l=long(32位)。
   ```c
   uint16_t host_val = 0x1234;
   uint16_t net_val  = htons(host_val);   // 发之前
   uint16_t back     = ntohs(net_val);    // 收之后
   ```
2. **文件/协议格式**：解析 PNG 头、ELF 文件这类"规定了字节序"的数据时，要按它规定的序摆字节。

**驱动场景**：外设寄存器映射到内存后，寄存器值的字节序取决于硬件设计——这也是为什么驱动工程师必须对大小端条件反射。

## 知识点 5：用代码判断大小端（手写必考题）

**写法 1：指针法（最常考）** —— 全程用你 02b 学的东西：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint32_t x = 0x11223344;
    uint8_t *p = (uint8_t*)&x;      // 02b 的强转：按字节看这块内存

    if (*p == 0x44)
        printf("小端 (little-endian)\n");   // 低字节(0x44)在低地址
    else
        printf("大端 (big-endian)\n");
    return 0;
}
```

逻辑：`p` 指向 x 的**最低地址**那个字节。小端存法低地址放低字节 → `*p == 0x44`。

**写法 2：联合体（union）法** —— 面试官爱看这个：

```c
union {
    uint32_t u;
    uint8_t  b[4];
} t;
t.u = 0x11223344;
printf("%s\n", t.b[0] == 0x44 ? "小端" : "大端");
```

union 原理：**所有成员共享同一起始地址**。`b[0]` 就是最低地址那个字节。大小端判断题几乎必考 union 写法。

> ⚠️ 打字面量时 `0x11223344` 从左到右是高位到低位：11 是最高字节，44 是最低字节。别看反。

### 顺手：union 的 sizeof

union 大小 = 最大成员的大小，再按最大成员对齐。`{uint32_t; uint8_t[4]}` → 4。

## 知识点 6：逐字节打印内存（综合题，理解神器）

把 0x12345678 的 4 个字节真的打出来看，大小端从"背的"变"看见的"：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint32_t x = 0x12345678;
    uint8_t *p = (uint8_t*)&x;

    printf("地址    内容\n");
    for (int i = 0; i < 4; i++)
        printf("%p  0x%02X\n", (void*)(p+i), p[i]);

    // 结构体对齐也看一眼：
    struct { char c; int i; char d; } s = {'A', 0x12345678, 'B'};
    uint8_t *q = (uint8_t*)&s;
    printf("\nstruct {char,int,char} 的内存：\n");
    for (int i = 0; i < sizeof(s); i++)
        printf("字节%2d: 0x%02X\n", i, q[i]);

    return 0;
}
```

**先预测每行输出再跑**。你会看到小端的"倒着存"和结构体 padding 的"空洞"（padding 字节值是随机垃圾，别被吓到）。
